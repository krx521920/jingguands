# Agent Note: FinStruct 文档兼容规则

Status: implemented

[English](2026-10-17-finstruct-document-compatibility.md) | 中文

## Problem

FinStruct 已发布的 v0.3 事件接口、解析输出和评测记录使用共同的固定字段标识符。为满足上游文风规则而改名，会破坏兼容性或使历史证据失真。五人团队的中文交接材料和已签署接口说明，与公开双语启动指南的读者也不同。审计回执必须保留实际执行的版本，包括没有发布标签的本地测试检查点。

## Decision

[复核清单](../../../../scripts/finstruct-doc-exceptions.json)将每项例外绑定到 FinStruct 所属的精确路径及文本 SHA256，计算前仅将 CRLF 归一为 LF。清单不接受通配符，分为三个独立类别：`protocol` 保留已复核的既有标识符和采集数据；`records` 保留实测版本引用；`teamDocuments` 保留原语言团队材料。这些是明确的复核决定，不表示目录内所有文件都获准豁免。[实现](../../../../scripts/finstruct-doc-exceptions.ts)拒绝畸形条目、范围外路径、缺失文件和内容变动。仓库没有自动刷新清单的命令。

术语检查仍拒绝精确复核文件以外的新用法。引用检查即使在已复核回执内，也仍拒绝禁用的组织 URL。本地 UI 事件 JSON 另有一项依据语法结构的例外：仅允许 UI 数据目录内 v0.3 信封的 `run_meta.code_version` 十六进制字符串；普通文字、其他键和畸形 JSON 仍受检查。版本字段记录实际执行的代码，不保证每个克隆都包含相应对象。

团队文档条目与翻译清单中的精确排除项对应，按选定的工作树或暂存区内容校验。内容改动后，必须补齐双语配对并移除例外，或复核更新后的原语言团队文档。根 README、公开启动指南、新 UI README 和包说明仍采用双语。新文档不继承豁免。团队文档仍接受 Markdown 换行与链接校验；格式整理保持 Markdown 语义。原始机器证据不会为了通过文档检查而改写。

本决定仅就已登记的 FinStruct 内容，部分取代[术语禁用规则](2026-08-26-ban-ambiguous-origin-label.zh.md)、[维护文档引用规则](2026-09-12-maintained-repository-references.zh.md)和[配对规则](2026-07-02-bilingual-docs-and-pairing-gate.zh.md)。三项通用规则继续有效，均不满足归档条件。

## Alternatives considered

**修改已发布字段或删除版本回执。** 这会改变团队共同协议，或移除复现证据，不能改善产品。

**排除整个业务目录。** 这会放过新文案和无关字段。精确内容摘要使修改必须经过复核，并保留其他所有检查。

**把每份团队交接材料都翻译成公开文档。** 中文团队以原语言维护签署决定、带日期的回执和本地工作记录。经过复核、逐项枚举的例外保留其读者定位，公开使用说明则提供对应的中英文版本。

## Consequences

清单增加维护成本：即使对已复核文件的其他内容做改动，也必须移除或复核例外。摘要一致只证明内容身份，不证明语义正确或评测成绩有效。审阅者必须核对每个清单变更的理由；文档检查通过不表示比赛要求全部达标。提交号检测仍受本地已有 Git 对象限制。

定向测试覆盖精确路径与内容匹配、记录变更与缺失、畸形清单、邻近路径、运行 JSON 键，以及继续拒绝普通文字与 URL。常规 `doc-sync` 检查项全部保留，清单校验在其中执行。
