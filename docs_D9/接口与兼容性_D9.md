# D9 接口与兼容性

## 1. 主接口

```javascript
import {attributeCase} from '../src_D9/attribution_D9.mjs';
const result = attributeCase({case_id, sides}, {documents, parses});
```

`documents` 是 case_id → A 0.3 信封；`parses` 可选，是 case_id → 同文件 SHA 的 evidence/0.9。有 parses 时优先采用原解析块，缺时使用 A.source.parse_meta.blocks。文件哈希在包内用于源版本一致性核对；本包未重下全部 PDF 独立重算文件 SHA。

`sides[]`：case_id、entity、field、value、raw_value、unit、block_id、quote；可补 event_id、file_sha256、page、caliber。数值推荐有限十进制字符串，禁止科学计数法和不安全大整数 Number；raw_value 保留公告原样。`unit=percent` 的数值按百分点，例如“2.5”表示2.5%，`fraction`需上游明确标准化后再送入。

可选 `caliber` 为本字段适用事实，每项必须包含 `value` 与 `provenance:[{block_id,page,quote,file_sha256?}]`。不得用没有出处的默认值填补。字段如下：

| 项 | 必需补充语义 |
|---|---|
| event_key / issuer_code | 同一明确事件/协议/交易编号与六位证券代码；引文有对应标签 |
| time | ISO日期；role为 as_of、period_start、period_end、event_date、publication_date；发布日期仅用于更正顺序 |
| currency | CNY/RMB/AED/USD等受支持代码或明确中文币名；元、$不独立定币种 |
| tax | 含税/不含税的明确原文；“是否含税未知”不成立，混合两种口径不猜对应值 |
| denominator | holder_shares/total_share_capital/net_assets/other＋原文definition；other不得省定义 |
| scope | single/cumulative，有原文支持；现版显式scope要求同词标注，中文本次/累计优先由A字段名或已核验header识别 |
| fx | value为1单位from对应to数量，另含from/to/date；现版计算证据格式支持“1 AED = 2 CNY”这种明确公式，币种代码大写；文本不同可保持疑点，不自动解析成隐含汇率 |
| tax_rate | value为百分数，原文明示“税率6%”等；同事件适用 |
| rounding | value为保留位数0–30，明确“四舍五入保留N位小数” |
| notice_number / correction | 原公告编号；correction含replaces_notice_number/replaces_file_sha256/replaces_field，明确“更正为”及被更正公告号、双方publication_date |

复杂财务归因仍需调用方确认事实的字段适用范围，例如汇率是否适用该笔合同、分母是否同一对象、观察日是否真是该字段时点。库验证提供的结构化事实与引文，不把任意同段关键词视为完整财务证明。不支持的文本形式返回不足，后续可增规则。

### 输出

`verdict` 兼容宗五态：corroborated / explainable_difference / restated / conflict / insufficient。

`attribution_code`为稳定规则码，`attribution`为判定说明；`sides`保留原值/原文/单位/页块/区域/表格坐标/原A出处；`computed`记录计算操作数、结果及used_source；`audit`记录不回写、不推汇率、不拆分；`trace`记录来源门槛及终止规则。`a_field_provenance`可与用例引用块不同，binding_method会标明独立核验，两个出处均保留。

`resolution` 必须一起消费：

- numerically_checked：已经完成实际数值核验。
- caliber_identified_only：只确定披露/不可比口径，不能显示为“全部差额已对平”。
- unresolved：证据不足，保留疑点。
- conflict_candidate：同口径矛盾候选，仍须人工终审。

`requires_review=true`不得隐藏。`model_explanation=null`是保留接口，模型不得覆盖verdict/规则码/计算。不能将insufficient渲染为不同事件、零金额或无冲突。

## 2. 魏插件接入

真实入口：`attribute_b.mjs --report B报告 --rules 方wei_adapter_D9.mjs --out 输出`。

原 B 报告保留不变，增补 `results[i].d9_context={documents,parses}`，并在对应 `consistency.conflicts[j]` 附加 `d9_input={case_id,sides}`。补充侧与原冲突的value/quote/doc/entity/field必须一致。数组中有多个同形冲突、字段名映射不明确，均拒绝按位置猜配。

完整受控输入见 `examples_D9/wei_b_input_D9.json`。接口兼容输出仍是 `{attribution,confidence,evidence}`，完整方判定序列化在evidence字符串中，供原入口无损承载；消费者若需结构化字段可JSON.parse。供宗评分用主runner报告，不能把attribute_b的attributions数组直接当cases数组。

```powershell
$report = (Resolve-Path .\examples_D9\wei_b_input_D9.json).Path
$rules = (Resolve-Path .\src_D9\wei_adapter_D9.mjs).Path
$out = Join-Path (Get-Location) 'docs_D9\validation_D9\wei_plugin_output_D9.json'
node .\peer_reference_D9\attribute_b_D9.mjs --report $report --rules $rules --out $out
```

上述输出是独立受控接口验证，不是31份真实B全量全链路。旧简化B冲突没有增强事实时应保守输出不足。
