## 二、出处结构：四级坐标

| 级别 | 载体 | 字段 | 用途 |
| --- | --- | --- | --- |
| L1 文件级 | `doc` | `doc_id`、`file_id`、`file_sha256`、`page_count` | 锁定「就是这份文件」，防掉包、防同名串证据 |
| L2 页级 | `pages[].page` | `page`、`width`、`height` | 人工定位与坐标归一化 |
| L3 区域级 | `pages[].blocks[]` | `block_id`、`region`、`role`、`text`、`text_raw`、`source` | 界面高亮框选、抽取层锚定 |
| L4 单元格级 | `pages[].tables[].cells[]` | `table_id`、`row`、`col`、`rowspan`、`colspan`、`region` | 表格数值精确定位（D3/D4 填充） |

一个块的实际样子：

```json
{
  "block_id": "d116fbfae_p001_b00003",
  "page": 1,
  "type": "TEXT",
  "role": "BODY",
  "text":     "为贯彻落实《教育强国建设规划纲要(2024一2035年)》及三年行动计划，",
  "text_raw": "为贯彻落实《教育强国建设规划纲要(2024一2035年)》及三年行动计划，",
  "region": [111.0, 163.78, 505.2, 175.78],
  "font_size": 12.0,
  "source": "TEXT_LAYER",
  "ocr_confidence": null,
  "degraded": false,
  "missing_reason": null,
  "table_ref": null
}
```

### 五条硬约束（写进契约的，不是建议）

1. **`region` 必填。** 取不到坐标的块不允许产出——团队 D3「禁止事后按数字搜索补出处」在结构上的落实。
2. **`text_raw` 必填。** 契约要求 `quote` 必须是**原文子串**。`text` 为可读性会在跨行处补空格（例如把链接 `https://app.cufe.edu.cn` 拆成 `https://app.cufe .edu.cn`），不是严格子串；`text_raw` 不插入任何字符，**quote 取它**。
3. **`source` 必填。** 标明这段字来自文本层、通道 A（系统/离线 OCR）还是通道 B（视觉大模型）。
4. **`doc_id` 由 `file_sha256` 派生，不用文件名。** 两份都叫「公告.pdf」的不同文件会得到不同 `doc_id`，证据不会互串（团队 D10）。
5. **cell 级出处与 block 级分开统计**，表格里的值必须能定位到行列。

## 三、坐标系约定（**必须冻结，改了下游全部返工**）

在 `doc.coord_system` 里显式声明，下游不用猜：

| 项 | 约定 |
| --- | --- |
| 单位 | PDF point（1 pt = 1/72 英寸） |
| 顺序 | `[left, top, right, bottom]` |
| 原点 | 页面**左上角**，y 轴向下为正 |
| 页面尺寸 | 每页随 `width` / `height` 给出 |

**页面渲染端的换算**：

```
归一化坐标 = region / [page.width, page.height]      # 得到 0..1
屏幕像素   = 归一化坐标 × [显示宽, 显示高]
```

**不要**假设 A4 或固定尺寸——`width`/`height` 每页都给了。

> 这一条是契约里**缺的**：`interface/event-envelope.schema.json` 的 `region` 只写了「[x1,y1,x2,y2] 页面区域坐标」，没声明单位和原点。已作为对齐项反馈给魏文宇，详见 `docs/契约对齐报告_D1.md` 问题 2。

## 四、怎么用

### 抽取层（魏文宇）

不要在抽完之后拿字段值回 `blocks[].text` 里搜索匹配——同一个数字在一份公告里常出现多次（正文一次、表格一次、交叉引用一次），搜索法无法断定字段真正来自哪一处。

**正确做法**：读输出顶层的 `handoff` 段，它已经给出映射：

```json
"provenance_from_block": {
  "block_id": "block.block_id",
  "page":     "block.page",
  "region":   "block.region",
  "quote":    "block.text_raw"
}
```

`handoff.source` 可**原样拷贝**进事件信封，字段集与契约完全一致。

`reading_order` 已按阅读顺序给出，直接按它遍历，不要自己按坐标重排。

### 展示层（陈家浩）

1. 按 `block_id` 找到块，取 `region` 和所在页的 `width`/`height`；
2. 按上面的换算公式转屏幕坐标；
3. 画高亮框时同时显示 `block.text`（可读），但**引用给用户时用 `text_raw`**。

`role` 可直接做样式区分：`TITLE` / `SECTION` / `BODY` / `HEADER` / `FOOTER`。页眉页脚已移出正文流但**保留在数据里**——它们可能承载日期、页码等有用信息。

## 六、已知边界（诚实标注，不掩盖）

1. **只实现文本层通道。** `SCANNED` / `MIXED` 页面会被判定并**如实降级**（写进 `quality.degrade_reasons`），暂不产出块。OCR 双通道是 **D4** 的工作。
2. **分栏检测尚未实现。** 阅读顺序目前是单栏自上而下，多栏排版会交错读。**D2/D4** 补。
3. **表格重建尚未实现。** `tables` 全部为空数组，但单元格级结构（`make_table_cell`）已在代码里定义好，D3/D4 直接往里填。
4. **「1.xxx」编号段落不识别为标题**，只认「一、」「(一)」。正文里也常用这种编号（例如「1.数据结构化提取。从…」），误判代价高于漏判——刻意的取舍。
5. **页码/页眉页脚的「多页重复出现」判定尚未实现。** 目前只按页面上下 8% 的几何位置判定，逐页独立，没有跨页比对。
6. **样例里 `text` 与 `text_raw` 恰好全部相同**（71/71），没有触发跨行西文的分叉。机制由构造用例 `test_text与text_raw在跨行西文处分叉` 单独保证。
