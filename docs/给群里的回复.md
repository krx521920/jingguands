> @宗博文 你 D1 报告中「需要确认」里写的那条 —— 张：确认 provenance、block_id、region 和表格定位能力，并提交 D1 解析产物。逐条回你：
>
> **1. provenance / block_id / region** —— 已按接口对齐，输出顶层有 `handoff` 段可直接取：
> ```
> block_id → block.block_id
> page     → block.page
> region   → block.region
> quote    → block.text_raw   ← 注意取 text_raw 不是 text
> ```
> 取 `text_raw` 的原因：`text` 为可读性会在跨行处补空格，实测会把 `https://app.cufe.edu.cn` 拆成 `https://app.cufe .edu.cn`，拿它当引文校验会失败。
>
> **2. 表格定位能力** —— 这是 D2 的主要工作，也是我实测踩到坑的地方。
>
> 先说问题：D1 的解析器在我自己造的样例（竞赛通知，**没有表格**）上区域重建一致率 100%，换成真实公告后 `pledge-001` 掉到 **81.8%**，第 1 页有 **68 个字符被两个以上的块重复覆盖**。根因是行聚类容差（中位字高 ×0.6）在表格里会把相邻两行并成一行 —— 那是股权质押情况表的**多行表头**，块的矩形互相压住 7.5pt。
>
> 修法：把「全页字符一起聚类」改成「**每个字符归属唯一所有者**」—— 表格单元格先占位，剩余字符才走段落聚类。单元格之间互不重叠（pdfplumber 的 cells 平铺整张表），flow 字符是它的补集，所以唯一归属是构造保证的，不靠调参。
>
> **结果**：段落×段落重叠 68 → **0**，丢字 193 → **0**，`pledge-001` 区域重建 81.8% → **98.9%**，另两份 **100%**。稳定 block_id 也验了，重复解析两次 id 序列与内容完全一致（含表格单元格块）。
>
> **3. 顺便补了你证据结构里我没有的字段**：
> - `source_type`（paragraph / table / cell / scan_region / document）—— D1 完全没有这个维度，补上了。你指标定义里「段落、表格/区域**分层统计**」靠它区分。
> - `document_id` 落在每个块上（我这边叫 `doc_id`），块被单独摘出来时仍自足。
> - 表格单元格以 `source_type=cell` 的独立块交付，`table_ref={table_id, cell_id, row, col}` 回指；`tables[]` 只留元数据，同一内容不放两处。
>
> **4. 三家字段名不一样，我固化了一张对照表**，在输出的 `handoff.field_aliases` 里：
> ```
> 页面区域：我 region   | 魏 region  | 你 bbox
> 原文引文：我 text_raw | 魏 quote   | 你 excerpt
> 文档标识：我 doc_id   | 魏 source.file_id(sha256:…) | 你 document_id
> 结构类型：我 source_type | 你 source_type | 魏未定义
> 表格/单元格：我 table_ref.table_id/cell_id | 你 table/table cell | 魏未定义

> 如果你觉得哪一列该改，说一声，现在改成本最低。

> **5. 还没做干净的（如实说）**：`pledge-001` 还有 **1 个块**区域重建不一致 —— 表格里有些字符落在 pdfplumber 检出的单元格矩形之外（多行表头 + 纵向合并），我按行兜底成 `source_type=table` 并标了 `degraded: true`，写进 `quality.warnings`。这类块的文本**可能是乱序的**，下游不该当可靠行级引文用。这是 D3「多层表头继承 + 合并单元格还原」的活。
