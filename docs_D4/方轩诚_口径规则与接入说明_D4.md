# 口径异常检查与接入说明 D4

负责人：方轩诚。2026-09-30。输入是已经定位到公告字段的事实；本模块负责口径和算术关系，不负责抽取、页面定位或认证原文。

## 1. 调用方式

```typescript
import {
  checkPledge, verifyPledge,
  type PledgeInput, type PledgeResult, type CheckResult,
} from "./src_D4/pledge/checks_D4.ts";

const result = checkPledge(input); // 默认 required：要求真实来源引用完整
const same = verifyPledge(input);  // 兼容旧函数名，同样经过 D4 检查
```

保留 D3 的六字段 JSON 输入，不需要给现有字段改名。新增策略通过第二个参数传入，不向原输入中塞字段。只有独立合成测试可以使用 `checkPledge(input, {evidenceMode: "synthetic_test"})`；其中所有参与计算的事实都必须 sampleType=synthetic。real 字段即使来源引用齐全，也不能通过该测试选项执行。

`parsePledgeInput()` 继续导出，**只检查输入结构**，不代表口径已通过。公开计算必须使用 checkPledge 或 verifyPledge。内部 `pledge_arithmetic_D4.ts` 保留 D3 语义用于回归，不应由业务直接调用。package exports 仅开放 checks_D4.ts。

## 2. 输入字段

| 字段 | 规则 |
| --- | --- |
| `id` | 非空记录 ID |
| `shares` | 质押股数 Fact 或 null |
| `ratio` | 披露比例 Fact 或 null |
| `denominator` | `{kind, fact}` 或 null；kind=holder_shares / total_share_capital / unknown |
| `ratioPolicy` | `{mode: exact或rounded, decimalPlaces: 0–12整数}`；必须明确，缺失不猜默认精度 |

Fact 的三部分如下；完整输入见 [示例 JSON](../examples_D4/pledge_input_D4.json)。

- `measure`：D2/D3 八字段 kind、rawText、rawValue、sourceUnit、qualifier、scope、status、denominator。股数单位为股/万股/亿股，比例为 %；rawValue 必须是纯十进制字符串（最长 120 字符）。20% 对应 `"20"`，不是 `"0.2"`。scope=single/cumulative/unknown；qualifier=exact/approx/at_most/null；status=present/explicit_zero/not_mentioned/unreadable。
- `context`：companyId、holderId、asOf、eventId 均为非空字符串或 null；asOf 必须为有效 YYYY-MM-DD。总股本快照的 holderId 可为 null；占持股时必须指定同一股东/股东组。累计余额按主体、时点比较，不强制单次 eventId。
- `source`：document、sha256、page、locator、sampleType。sha256 为 64 位十六进制或 null，page 为从 1 起的整数或 null，sampleType=real/synthetic。document 和 locator 必须非空。真实字段引用缺 sha256 或 page 时转复核；空 locator 属于格式错误。

有值比例的 `measure.denominator` 在原文未明确时允许保留 null。D4 会保留其标准化数值，例如 `20.00% → "20"`，并返回 UNKNOWN_RATIO_DENOMINATOR；**单位标准化不等于已授权关系计算**。顶层即使另有一个持股数，也不能补造该比例的原文分母。

缺失/无法读取时 rawValue、sourceUnit、qualifier、denominator 必须为 null；保留 status 与原始出处。明确零必须为 explicit_zero + exact。不得以零代缺失，也不得把计算值回写原文。

## 3. 执行顺序与边界

1. **检查结构与单字段标准化。** 错字段、单位、日期、非法数字和小数股返回 invalid。结构不成立时不继续解释其业务含义。
2. **检查独立合法性。** 精确质押数/分母为负、明确零分母、精确质押比例超出 0–100%、精度声明冲突等，即使缺少其他依据也可单独报告；仍不做关系计算。该范围只适用于本质押接口，不推广至净资产比率等其他业务。
3. **收集比较依据异常。** 分母是否明确且有值；股数与比例是否同单次/累计；公司、时点、股东是否一致；单次事件是否一致；参与计算的值是否为 exact；来源引用是否满足模式要求。可安全检查的独立异常一起输出。
4. **只有依据全部通过才计算。** 复用 D3 精确算术，检查质押股数是否大于同口径分母，再检查披露比例是否匹配，或按充分依据推导缺失字段。

任一前置检查失败，`audit.prerequisitesMet=false`，`calculation=null`、`comparison=null`。原始数值可保留在 normalized，方便人工复核，但不能展示为已经完成的比例关系结论。

**重要修正：** 假设质押股数 600 万、给出的持股数 500 万，但持股数属于另一股东或另一日期。D3 可能先报“股数超分母”；D4 先返回口径不一致，不能根据不同口径的两个数字判断矛盾。若确认同主体同时点且依据齐全，才报告 SHARES_EXCEED_DENOMINATOR。

约数/上界无法确认精确大小关系。例如“约 0 股”的分母不是“明确 0 股”，只返回 NONEXACT_FACT；不能因为规范化数值恰好为零，就把约数升级为明确零分母异常。

## 4. 比例和数值关系

| 关系 | 核验方式 |
| --- | --- |
| 股数 → 百分点数 | 股数 × 100 / 已确认分母股数 |
| 精确比例核验 | 交叉相乘比较精确有理数，展示舍入不参与判定 |
| 已舍入比例核验 | 计算比例按显式小数位 ROUND_HALF_UP 后比较，不附加固定容差 |
| 精确比例 → 股数 | 比例百分点数 × 分母股数 / 100，非整股不取整，转复核 |
| 舍入比例 → 股数 | 返回舍入允许的闭区间整股范围，value=null，不把中心值当事实 |
| 未知分母 | 不通过股数÷比例“求分母”后循环验证自己 |

全部财务数值采用十进制字符串或 BigInt 分数；Number 只用于页码、日期校验和精度等元数据。保留占持股/占总股本、本次/累计四种组合。累计指统计时点未解除的质押余额，不是把历史全部发生额相加。

明确 0% 若是两位舍入值，也可能对应少量非零股份；是否可以反推精确零股由明确的 ratioPolicy 决定。显示值相同不等于精确相等，例如 1/3×100 与精确 33.33% 不相等。

当原文某字段缺失/无法读取，但另一个分子字段与分母的独立依据充足时，可以返回 calculated；缺失原字段仍保持 null 和原 status。只有原始输入不足才禁止推导，不把有依据的数学计算称作原文披露。

## 5. 输出和前端展示

保留 id、status、reasons、normalized、calculation、comparison；tool 更新为 pledge_check_D4，version 更新为 0.4.0。

| 状态 | 含义 |
| --- | --- |
| verified | 同口径算术通过，不代表原文真实性通过 |
| mismatch | 同口径可比较，但比例数值不匹配 |
| calculated | 依据足够，推导计算值或区间；不可回填原文 |
| needs_review | 不可确认口径/依据，或反推无合适整股解 |
| invalid | 输入格式或独立合法性错误，或确认同口径后股数超分母 |

新增 `anomalies[]`：code、severity(error/review)、field、message。`reasons[]` 继续保留 code/message 便于旧页面读取；结构正确时可返回多个独立问题，同一原因码可能针对不同字段出现。存在独立 error 时整体为 invalid，仍保留其他 review 原因。

新增 `audit`：

| 字段 | 意义 |
| --- | --- |
| evidenceMode | required 或 synthetic_test |
| evidenceStatus | not_checked / incomplete / located / synthetic |
| prerequisitesMet | 是否已经满足调用算术核验的全部前置依据；不代表最终一定通过 |
| sourceContentsVerified | 固定 false，本工具没有读取并核对公告内容 |

`located` **只表示来源引用字段齐全**。仅凭一个哈希字符串、页码和 locator，无法确认原文真的存在、值是否正确或哈希是否匹配。原文内容认证仍由团队解析/证据模块执行；不得把此字段映射为“来源已核真”。

## 6. 兼容迁移

- 保留 D3 输入结构及 verifyPledge 名称；修改导入路径为本包公开入口即可。PledgeInput、Fact、Basis、PledgeResult 类型名继续导出，新增 CheckOptions、CheckResult。
- 结果增加字段，并升级 tool/version；按工具名或版本字面量分发的调用方需要更新。D4 不声称输出字节与 D3 完全一致。
- 默认更严格：D3 合成数据不能在 D4 默认模式下当作真实依据。测试必须显式选 synthetic_test，实际数据需补齐经过上游核对的引用。
- 比例原文缺分母由 D3 invalid 改为 needs_review；其他部分错误码更具体，例如负值 NEGATIVE_VALUE、零分母 ZERO_DENOMINATOR、字段标准化失败 INVALID_MEASURE。依赖旧 reasonCode 的前端应参考边界用例更新。
- 正常同口径输入的计算式、精确分数、展示值和舍入区间与 D3 一致；D2 默认 normalize 行为不变。只有 D4 显式允许未知比例分母参与单位标准化，且随后阻断关系计算。
- D3/D2 旧源文件未改写。当前团队仓库未发现可直接调用的质押业务接口，本次验证的是公开模块、输入输出和 npm 运行路径，没有宣称完成实际 Cordis 注册或网页联调。

## 7. CLI、执行记录和退出码

```powershell
npm test
npm run demo
npm run check -- <团队输入_D4.json>
```

CLI 接收一个六字段对象或非空对象数组，支持 UTF-8 BOM；不是直接传边界测试的外层用例对象。批量结果含每条原始输入、标准化值、异常、计算过程、Node 版本、模式、时间、输入文件哈希、实现文件哈希及状态计数。

需要纯 JSON stdout 时使用 `node src_D4/pledge/cli_D4.ts <文件>` 或 `npm run --silent check -- <文件>`；普通 npm run 会额外输出脚本标题。合成数据加 `--synthetic-test`，例如 `npm run --silent demo`。

退出码：0=成功处理完批次（允许 mismatch/needs_review）；2=至少一条 invalid（仍输出全批次）；1=参数、文件或 JSON 解析失败（错误 JSON 写 stderr）。业务是否通过必须读取 status，不能只看退出码。运行只读输入并向 stdout/stderr 输出，不访问网络或自动写回文件。
