# 质押口径与比例核验 v0.3.0（D3）

负责人：方轩诚。日期：2026-09-29。交付范围是已确认事实字段的标准化、数值换算和比例核验，承接 D2 的八字段 `MeasureInput`；新增主体/时点/事件及出处外层字段。D1 中“不反推股数/比例”描述的是 D1 模块边界，本次按 D3 任务增加有明确分母时的独立推导，不更改原始事实记录。

## 1. 四种质押口径

设本次质押为 S，统计时点的累计未解除质押余额为 C，同一股东或明确股东组的持股数为 H，公司同期总股本为 T。

| scope | denominator.kind | 公式 | 含义 |
| --- | --- | --- | --- |
| `single` | `holder_shares` | S / H × 100% | 本次质押占该股东持股 |
| `single` | `total_share_capital` | S / T × 100% | 本次质押占总股本 |
| `cumulative` | `holder_shares` | C / H × 100% | 累计质押余额占该股东持股 |
| `cumulative` | `total_share_capital` | C / T × 100% | 累计质押余额占总股本 |

“累计”在本工具中指截至统计时点的已质押余额，不是历史所有质押发生量之和。原文语义尚未核实，应标为 `unknown`。工具不把本次值加到累计值，不将累计余额跨期相加，不从累计差额猜测本次值，也不处理解除质押后的余额滚动。

同一公告同时披露四种口径时，传入四条独立记录。股东组使用经上游确认的稳定组 ID，不能把单个股东与一致行动人合计视为同一分母。

## 2. 调用入口与输入

```typescript
import { verifyPledge } from "./src_D3/pledge/pledge_D3.ts";
const result = verifyPledge(input); // unknown → PledgeResult，JSON 可序列化
```

顶层固定六个字段。JSON 边界拒绝额外或缺少的字段，防止拼错字段名后静默跳过。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | 非空字符串 | 调用方记录 ID，用于对应抽取结果 |
| `shares` | `Fact` 或 `null` | 质押股数；`measure.kind=shares` |
| `ratio` | `Fact` 或 `null` | 披露比例；`measure.kind=ratio` |
| `denominator` | `{kind, fact}` 或 `null` | kind 为 `holder_shares` / `total_share_capital` / `unknown`；fact 必须为股数 |
| `ratioPolicy` | `{mode, decimalPlaces}` | `mode=exact` 或 `rounded`；小数位为 0–12 的整数 |

`Fact` 包含 `measure`、`context`、`source` 三部分。完整可运行 JSON 见 [演示输入](../examples_D3/pledge_input_D3.json)。

### measure：复用 D2

八字段为 `kind`、`rawText`、`rawValue`、`sourceUnit`、`qualifier`、`scope`、`status`、`denominator`。标准化后仅新增 `value`、`unit`，原文字段不改写。D3 质押接口只接受 shares/ratio；复用的 D2 通用函数仍支持 amount。

- 股数源单位：股、万股、亿股；比例源单位：`%`。`rawValue` 使用最多 120 字符的纯十进制字符串，无千位分隔符、空格、科学计数法或百分号。
- `rawValue="20"` 且 `sourceUnit="%"` 表示 20%，不是 0.20，也不是 2000%。若模型输出小数比率，上游必须先确认语义，不能仅改单位标记。
- `scope` 取 single/cumulative/unknown；股数与披露比例两个**分子**的 scope 必须一致。分母是同期持股/总股本快照，其 `scope` 不参与单次/累计比较，示例使用 unknown，通过 `context.asOf` 明确时点。
- 质押数值参与计算时须为 `qualifier=exact`；approx、at_most 保留为待复核，不当作精确事实。精度策略是另一维度：`exact` 修饰词表示原文没有“约”“不超过”，不意味着比例没有小数位舍入。
- `not_mentioned`、`unreadable` 时 rawValue/sourceUnit/qualifier/denominator 均为 null。可用 `Fact` 保留缺失状态；直接用 null 表示该条工具请求未提供该事实。
- 数值为精确零时 status 必须为 explicit_zero；present 不能冒充明确零。百分比栏的明确零仍可能来自显示舍入，是否能推出零股由 ratioPolicy 决定。
- 比例有值必须给出 `measure.denominator.kind` 与非空 `definition`。该 kind 必须与顶层分母种类一致；持股与总股本不能混用。定义文本由上游确认，本工具不以自然语言理解代替字段关联核验。

### context：阻止跨主体、跨时点、跨事件混算

固定字段：`companyId`、`holderId`、`asOf`、`eventId`，均为非空字符串或 null。

- 所有参与计算的事实必须具备相同的 companyId、asOf；asOf 是原文统计日期，格式为合法 YYYY-MM-DD。
- 质押股数、披露比例必须具备相同的 holderId。占持股时分母也必须是同一 holderId；总股本属于公司，其 holderId 可以为 null。
- single 的股数与比例必须具备相同 eventId；累计余额不依赖单次事件 ID。分母快照无需事件 ID。
- 缺失上下文返回 needs_review。工具不把上传日期、公告发布日期自动当作统计时点。

### source：透传出处，不补造出处

固定字段：`document`（文件名/标识）、`sha256`（64 位十六进制或 null）、`page`（从 1 开始或 null）、`locator`（区域/块/单元格或降级说明）、`sampleType`（real/synthetic）。缺少真实出处时用 null 和降级说明，禁止用合成页码冒充证据。

本工具只验证这些字段的格式并透传，不打开公告、不核对哈希与原文是否匹配；`verified` 只表示同口径数值关系通过。真实来源核验由解析/定位链路负责。真实案例应提供文件 SHA-256、页码和稳定 locator；未提及字段的 locator 应注明已核验的页面范围。

## 3. 精确运算与舍入

1 万股=10,000 股，1 亿股=100,000,000 股。标准化沿用 D2 字符串十进制移位；除法和比较使用 BigInt 有理数，金融数值不经 `Number`/`parseFloat`。

**股数 → 比例：** `比例百分点数 = 质押股数 × 100 / 分母股数`。`calculation.exactFraction` 保存完整分子/分母；展示值按 decimalPlaces 使用正数 ROUND_HALF_UP。非终止小数不得通过展示文本进行精确比较。

**比例 → 股数：** `股数 = 比例百分点数 × 分母股数 / 100`。mode=exact 时必须得到整股，否则 needs_review；不擅自四舍五入股数。

**已有股数与披露比例：** exact 模式采用交叉相乘精确比较；rounded 模式将计算比例按指定小数位 ROUND_HALF_UP 后，与披露比例比较。没有额外的固定 0.01 或浮点 epsilon 容差。披露值必须可由指定小数位精确表示，例如 20.001 不能声明为两位。

**舍入比例反推：** mode=rounded 时只返回 `possibleWholeShares.min/max`（闭区间整数字符串），`calculation.value=null`。令披露比例 r 的最小显示单位为 u=10^-decimalPlaces，则真实比例区间为 `[r-u/2, r+u/2)`，先与 `[0,100]` 相交，再除以 100、乘分母并取整股下上界。不存在整股解则 needs_review。即使区间只有一个整数，也保留其“由舍入区间推导”的属性。

| 示例 | 预期处理 |
| --- | --- |
| 1,000,000 / 5,000,000 × 100 | 占持股 20.00% |
| 1,000,000 / 50,000,000 × 100 | 占总股本 2.00% |
| 1 / 3 × 100，披露 33.33%，两位舍入 | 核验通过；exact 模式不通过 |
| 2,469 / 20,000 × 100 = 12.345% | 两位 HALF_UP 得 12.35%，不接受 12.34% |
| 分母 5,000,000，披露 20.00%，两位舍入 | 可反推 999,750–1,000,249 股，不能断言 1,000,000 股 |
| 分母 5,000,000，披露 0.00%，两位舍入 | 可能为 0–249 股，不能断言无质押 |
| 分母 5,000,000，比例明确精确为 0 | 可反推 0 股，仍标记为计算值 |

decimalPlaces 必须由原文显示精度或经确认的格式规则确定；本工具不从数值大小推测，也不静默切换 exact/rounded。

## 4. 输出与状态

`PledgeResult` 包含 id、tool、version、status、reasons、normalized、calculation、comparison。计算含公式、操作数、精确分数、展示/区间说明、scope 和 denominatorKind。返回值无 BigInt 对象，所有财务数值均为十进制字符串。

| status | 含义 | 下游建议 |
| --- | --- | --- |
| `verified` | 输入有股数和比例，满足同口径条件并通过算术检查 | 展示通过，同时保留出处核验的独立状态 |
| `mismatch` | 可比较，但披露值与指定精度下的计算值不同 | 展示双方数值、原文出处与比较规则 |
| `calculated` | 只提供了一个可用分子字段，已推导另一字段或区间 | 显示“计算值”；不得改写缺失/无法读取的事实 |
| `needs_review` | 缺分母、口径/上下文不一致、约数、反推无整股解等 | 显示原因，不强行判数值矛盾 |
| `invalid` | 数据格式错误、负质押、非正分母、超过 100% 等 | 修正上游输入；不得作为正常核验通过 |

`reasons` 提供机器可读 code 和中文说明；具体 reasonCode 的固定预期见 [53 条用例](../tests_D3/fixtures/pledge_cases_D3.json)。本工具返回遇到的首个阻断原因；复杂多异常归因与跨公告关联不属于 D3。

## 5. 与团队代码接入

将整个 `src_D3` 目录复制到团队选定的业务目录，保留相对导入路径。魏文宇的抽取插件在 execute 中将已绑定出处的事实映射为 PledgeInput，直接调用唯一计算入口；网页和命令行都使用同一个函数，避免各实现一套舍入规则。

```typescript
import { verifyPledge } from "./src_D3/pledge/pledge_D3.ts";

// 放入团队现有、已注册的质押抽取/核验工具 execute 内。
// extractedAndLocated 必须先映射为本文六字段协议。
const arithmeticResult = verifyPledge(extractedAndLocated);
// 交给原工具的结构化输出、日志及页面导出链路；保留原始抽取字段。
```

团队仓库使用 DeepSeek Harness/Cordis。注册新模型工具还需遵循该仓库的 defineTool、schema、effect 注册和会话日志要求。本包提供纯计算入口和离线 CLI，没有冒充已经注册的 Cordis 插件。上面的调用片段应嵌入已有插件；若新增插件，维护者需提供对应工具参数 schema 与部署配置。本次未改动仓库的 agent loop、packages 或部署配置。

D2 复用文件与原文件字节一致，D3 的股数非负、0–100% 等质押业务限制在 verifyPledge 中实施，不改变 D2 对“减少量负股数”的通用标准化行为。

## 6. 命令行、日志与复现

在交付根目录运行：

```powershell
node src_D3/pledge/cli_D3.ts examples_D3/pledge_input_D3.json
node --test src_D3/pledge/__tests___D3/pledge.test_D3.ts
```

CLI 接受一个对象或非空对象数组，支持 UTF-8 BOM，stdout 输出一个 JSON。运行记录包含 Node 版本、开始/完成时间、输入文件绝对路径与 SHA-256、三个实现文件的 SHA-256、每条原始输入与结果、状态计数。结果含计算过程；不另写外部文件，不访问网络。下游保存 stdout 即可留存计算审计记录。重复运行的时间与文件路径可不同；相同输入的 `results[*].result` 确定一致。

退出码：0 表示成功处理完批次，允许包含 mismatch/needs_review；2 表示至少一条 invalid，仍输出全批次结果；1 表示命令参数、文件访问或 JSON 解析失败，错误 JSON 写入 stderr。批次是否业务通过必须读取 status，不能仅判断进程退出码。

运行与测试不需 tsc。可选严格类型检查：在已安装开发依赖的集成目录执行 `tsc --noEmit -p tsconfig_D3.json`。按 `_D3` 归档清单不存在 package.json，因此本 tsconfig 显式使用 ESM 和 bundler 解析、noEmit，仅检查类型；实际执行由 Node 24 自带类型剥离完成，所有本地导入均写出 `.ts` 后缀。
