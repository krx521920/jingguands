## 五、发现

### P0-1 权威批次数据未入库 → clone 后页面看不到任何权威数字

**事实**
- `workspace/cjh/page_prototype/.gitignore` 含 `data_unified/`（注释写"宗分支已入库同一批，3.0MB / 32 份不重复入库"）。
- `git ls-tree -r e7bec616` 下 `data_unified` 条目 **0 个**；`/evaluation/` 同样被 ignore。
- 实测：**无数据 → 三张指标卡 null + "0 份入口径"**（见 §四右列）。

**为什么是 P0**
1. 评委/队友是 **clone 后运行**，不是到 `zongbowen` 分支取数；`/evaluation/` 在页面分支被 ignore，页面根本拿不到那条路径。
2. 现状比改造前更难解释：改造前页面显示 548 字段 / 71.53%（口径混、但非零），现在显示 **null / 0**——同一屏出现"材料 437/437 vs 页面 null"，评审第一眼仍是矛盾。
3. R1 的承诺（默认权威口径）在**别人机器上无法呈现**，等于只在陈本机成立。

**建议（任选其一，按优先级）**
- (a) 直接入库 `data_unified/`（约 3MB，内容即魏 D11 首测信封，已在 `weiwenyu` 分支公开，不存在泄密问题）；
- (b) 不入库但**缺数据要显式报错**并给出取数命令（现在是静默 0 份：`/api/metrics` 返回 200 + null，容易被当成"指标就长这样"）；
- (c) 把权威目录指到 clone 后必然存在的路径。

**验收**：clone 后只跑 `node server.js`，`/api/metrics` 的 `data_source.anchor.matches` 为 `true`、`summary.fields_total` 为 `606`。
