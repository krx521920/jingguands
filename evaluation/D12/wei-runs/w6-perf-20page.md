# W6 · 20 页公告性能专项实测（回应宗 2026-10-08 待办三项）· 2026-10-08

## 标准与口径

- 标准原文（D12 完成标准）：「**3 份 20 页文本公告各 ≤90 秒**」
- 实测口径：**A 流端到端**＝解析 JSON 载入 → 块级标注 → 模型调用（temperature=0，含分块多轮）→ 后处理/校验 → 信封落盘。
  PDF→解析不在本口径内（张的阶段耗时表已实测：纯本地计算，30 份/301 页总耗时中位 160ms、每页中位 43.8ms——20 页解析 ≈1s，占 90s 预算 ~1%）。
- 计时方式：`run_batch --jobs 1 --no-cache`（冷跑、逐份墙钟），批次 `runs/batch-20261008T150554`（真实 3 份）＋`runs/batch-20261008T150658`（合成件复跑）。

合成方法（可复现）：`D5-EQC-002.parse.json` 截取 `pages[0..19]`，`reading_order` 同步过滤至保留块（526 块），`doc.page_count` 与 `handoff.source.parse_meta.page_count` 置 20。

## 结论

1. **3 份 ≥20 页真实公告各 ≤90 秒：达标**（3.57s / 12.75s / 19.34s，最大值为标准的 21%）。
2. **精确 20 页合成样本：11.99s，达标**（标准的 13%）。
3. 压力位：**64 页（=标准 3.2 倍页数）19.34s 仍达标**——超线性增长点在 >60K 标注字符触发的分块二轮调用（D5-EQC-002 恰为 2 块），即使如此 64 页也仅用预算 21%。无外推：所有数字均为直接实测。
4. 耗时结构印证张的结论：瓶颈在模型调用轮次（冷跑单轮 3–13s），解析侧可忽略。
