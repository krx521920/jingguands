## 二、前置闸门（不过闸门不许跑）

| 闸门 | 判据 | 复核命令（任何机器可跑） |
|---|---|---|
| ① PDF 未调包 | 3/3 == 锁中 `file_sha256` | `git show HEAD:evaluation/D13/strange-samples/<file>.pdf \| sha256sum` |
| ② parse 未调包 | 3/3 == 锁中 `parse_sha256`（**仓库字节**） | `git show HEAD:evaluation/D13/strange-samples/<file>.parse.json \| sha256sum` |
| ③ 锁自洽 | `parse_sha256 == lock_semantics.product_sha256.value`；`file_sha256 == lock_semantics.primary.input_sha256` | 读 `evaluation/D13/陌生样例-锁.json` |

**基准一律是 HEAD 的仓库字节**（不是工作区磁盘字节）。旧的工作区值保留在 `parse_sha256_worktree_crlf` 字段，仅作根因留档，**不作为闸门期望值**。

**闸门不绿 → 停，记录，不做执行。** 跑了也不算数：无法证明跑的是锁定的输入。

## 四、判据（5 条，先说什么算失败）

| # | 判据 | 失败长什么样 |
|---|---|---|
| 1 | **值层**：关键字段与私有预期逐项一致 | 值不同即失败；**状态标签翻转且值均为空**单独列，不算值层失败但必须归因 |
| 2 | **证据回锚**：每个有值字段带 `block_id` 或 `quote`，且 `quote` 能回锚到所在块 | 有值无出处；出处指向不存在的块；`quote` 在块内找不到 |
| 3 | **事件粒度**：STR-04 必须区分「解除质押」与「质押延期购回」 | 两者合并成一个事件即失败（这是 D11 暴露过的能力点） |
| 4 | **方向/形态**：STR-05「收到中标通知书」≠「已签合同」 | 把中标通知书说成合同已签 |
| 5 | **币种/主体保真**：STR-06 增持均价为港元（H 股），按人民币处理即失败 | 未标币种或强行折算；主体写成上市公司名而非实际股东 |

补充：**未披露 ≠ 零，未提及 ≠ 无**——`not_disclosed` / `not_mentioned` / `unreadable` 三态要按契约语义落，不得用 0 或空串糊过去。

## 五、开封比对（执行前不公开预期）

1. 私有预期由**评测侧本地保存**，执行前只公开 `expectation_sha256`；
2. 执行方交回原始输出后，**当场解锁比对**，比对由我执行；
3. 对不上**记失败**，不得回头改预期、不得裁剪样本；
4. 比对脚本与结果一并入库（`evaluation/D13/`），含输入哈希与输出哈希。

## 七、边界（如实写在前面）

1. **评测侧没有模型密钥**——半封闭环境下密钥只走环境变量、不入库。因此"冷跑"由持有密钥的一方执行（魏侧或团队指定人），评测侧**核输出**；本机只能做重放与比对。
2. 样本只有 **3 份**，用于"未见过输入 + 无隐藏步骤"的现场检验，**不构成统计意义上的能力估计**。
3. 三份均为**文本型 PDF**，扫描降级路径仍只由语料内对抗样本覆盖。
4. 解析侧可复现性另有张的 B1 诊断（入库 parse 与当前源码块分组存在差异）——抽取侧消费的是**入库 parse 字节**，不受该差异影响；但若今后要重跑解析，须先按张的规则升 `parser_version`。
