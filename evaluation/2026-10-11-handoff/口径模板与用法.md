# 报告口径头 · 模板与用法（2026-10-11）

出表：宗（评测侧）｜工具：`report-header.mjs`｜起因：**同一件事在不同批次/版本下会给出不同的数**

## 一、为什么必须有（真实教训）

| 实例 | 数 | 差在哪 |
|---|---|---|
| 缓存重放（**D12 时点**） | **31/31 逐字节** | 未施加 D17 无值族不变量 |
| 缓存重放（**施加 D17 不变量后**） | **28/31 逐字节 ＋ 4 处无值 `standardized` 翻正**（值层 31/31） | 多了一次规则修正 |

两个数都对。**但只写一个数、不带批次与码版本，就是在制造"同名两个值"**——这正是我们在展示层上抓出的那类问题。
另两例：`229/229`（权威 31 份，排除 DEMO）vs `235/235`（含演示件 32 份）；`437/437`（准确率）vs `437/606`（覆盖率）。

## 二、模板（任何引用比率的报告，头部原样贴）

```markdown
> **报告口径头**（引用任何比率前必读）
> 批次 id：<批ID>　|　code_version：<码版本/提交号>　|　输入锚点：<anchor_sha256>
> 生成日期：<YYYY-MM-DD>　|　口径与分母：<本次口径说明，含分子/分母>
> 提示：批次或码版本不同的两个数**不可并列比较**；跨版本对照必须写明"测于 <批次>/<码版本>"。
```

生成命令：

```bash
node evaluation/2026-10-11-handoff/report-header.mjs \
  --batch D12-A --code-version weiwenyu@dc4080ac --anchor 381c760f… \
  --caliber "缓存重放：D12 时点 events 逐字节 31/31；施加 D17 不变量后 28/31＋4 处翻正（值层 31/31）"
```

## 三、三条硬规矩（写进纪律）

1. **批次或码版本不同 → 两个数不许并列**；要对比就写"测于 <批次>/<码版本>"。
2. **每个比率必须带分子/分母**（"100%"不是数，"437/437"才是）；分母口径不同就分列。
3. **跨版本复现要求**：报"重放一致"时必须说明**是否已施加当期规则修正**（本例：D17 不变量）。

## 四、与新批封存工具的配合

新批（T1/T2/T3）流程：`lock-new-batch.mjs` 出锁与锚点 → 跑分 → 报告头填 `--anchor <该批锚点>`。
这样任何一份报告都能反查到"跑的是哪一批、哪版代码、输入锚点是什么"。
