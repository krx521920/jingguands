# D9 误报分析

日期：2026-10-05
口径：**先归因，再判矛盾**。误报 = 把可解释差异判成矛盾；漏报 = 真矛盾没判出来。

## 一、本脚本判定的五类错误

| 代码 | 含义 | 触发条件 |
|---|---|---|
| `FALSE_POSITIVE_CONFLICT` | 误报 | 期望非 `conflict`，报告却给 `conflict` |
| `FALSE_NEGATIVE_CONFLICT` | 漏报 | 期望 `conflict`，报告未给 `conflict` |
| `CONFLICT_WITHOUT_DUAL_EVIDENCE` | 无据指控 | 判 `conflict` 但不足 2 侧带 `block_id + quote` |
| `FORCED_COMPUTATION:<name>` | 强行换算 | 用汇率/税率但 `computed[].used_source` 为空 |
| `CONCLUDED_CONFLICT_FORBIDDEN` | 越界结论 | 用例显式 `must_not_conclude: conflict` 仍判矛盾 |

## 二、对抗报告实测（故意注入 5 类错误）

| 用例 | 类别 | 期望 → 报告 | 抓到的错误 |
|---|---|---|---|
| `D9-RULE-002` | 互证 | corroborated → conflict | 误报 + 无双侧证据 |
| `D9-RULE-010` | 本次/累计口径 | explainable_difference → conflict | 误报 + 越界结论 |
| `D9-RULE-012` | 比例分母口径 | explainable_difference → conflict | 误报 + 越界结论 |
| `D9-RULE-015` | 币种折算 | explainable_difference（含无依据汇率） | 强行换算 |
| `D9-RULE-020` | 真矛盾 | conflict → explainable_difference | 漏报 |

**结果：PASS 15 / FAIL 5；误报 3、漏报 1。**

## 三、公开语料层面的误报基线

- 魏 B 引擎在公开 20 组封存配对、以及 D8 的 8 组不同事件对照上均为 **conflicts = 0、误报 = 0**。
- 说明公开语料里**不存在真矛盾**：任何在公开对照上被判 `conflict` 的，**一定**是误报。
- 因此 D9 的"真矛盾"能力无法用公开语料证伪，只能用受控构造（`D9-RULE-020`）验证"能不能判出来"，用公开对照验证"会不会乱判"。

## 四、本轮暴露的三个高风险点（给 B 侧）

1. **本次 vs 累计**：`本次质押 2,100,000` 与 `累计质押 50,350,000` 数值差 24 倍，若不带口径标签直接比，必然误报。→ 归因时先取 `*_this_time` / `*_cumulative` 字段语义。
2. **比例分母**：`占其所持 2.4%` 与 `占总股本 0.99%` 是同一笔质押的两个口径，不可互比。
3. **币种折算**：`AED 173,800,000` 与 `CNY 317,915,000` 是同一金额两种口径，取公告明示折合值；缺汇率依据时不得自行换算。

## 五、结论

评分器已能把"数值不同"与"矛盾"区分开：可解释差异判 `conflict` 会立刻计误报，真矛盾没判出会计漏报，无双侧证据或强行换算会直接判失败。D9 的 20 条用例可复现、可回归。
