## 六、机制化防线（2026-10-09 新增）

针对"**资产改了、引用它的文档没跟着改**"这一类（12 次自纠里最后 3 次全是它），已把**文档一致性**做成机器可查：

### `evaluation/integration/check-docs.mjs`

| 规则 | 查什么 | 能拦住我犯过的哪类错 |
|---|---|---|
| **C1** 引用存在性 | 文档里 `` `path/file.ext` `` 形式的仓库内引用是否真实存在（按文档目录→祖先目录→仓库根逐级解析；上游/他分支路径走显式白名单） | 样例改名/移动后文档仍指旧路径 |
| **C2** 废弃枚举 | 出现在**非勘误语境**的错误枚举值（如 `held_shares`，应写 `holder_shares`） | **第 14 次自纠**（转发文档里带错枚举） |
| **C3** 近似笔误 | 形如枚举但**与某个枚举仅差 1 字符**的 token（疑似笔误） | 枚举打错字 |

**例外必须显式**：外部/上游引用登记在 `check-docs-allow.json`，**新增例外要写理由**——不藏在启发式里。

### 已验证（反向测试）

向 `evaluation/` 注入 3 类错误 → **全部被抓**：

```
C2_DEPRECATED_ENUM  held_shares        → 应写 holder_shares
C1_MISSING_FILE_REF evaluation/D99/... → 仓库内未找到
C3_NEAR_ENUM_TYPO   holder_share       → 与 holder_shares 差 1 字符
```

清理后回到 **PASS（81 篇文档、0 问题）**。
