# D7 分层字段规范（方案 C 落地件）

评测侧（宗）｜2026-10-05｜依据：`D7-normalization-adjudication.md`（已落签框架）

## 一、新增字段（不改 schema 0.3 既有键）

```jsonc
{ "value": 2100000, "status": "extracted", "standardized": true,
  "unit_basis": "block_header",     // cell_header | block_header | table_hint | none | conflict
  "evidence_strength": "medium" }   // strong | medium | weak | none | conflict
```

**唯一允许 status 变化的情形**：`evidence_strength ∈ {none, conflict}` → `needs_review`。其余一律保持 `extracted`、`value` 不变。

## 二、分级判据

| 级别 | 判据 | unit_basis | evidence_strength |
|---|---|---|---|
| 强锚 | `source_type=cell` ∧ `table_id/cell_ref` 匹配 ∧ `quote∈块` | `cell_header` | `strong` |
| 中锚 | 块级 `header_path` 锚 | `block_header` | `medium` |
| 弱锚 | 表级/行级 hint 或跨页跨列回退 | `table_hint` | `weak` |
| 无锚 | 三者皆不成立 | `none` | `none` |
| 冲突 | 两处锚互相矛盾 | `conflict` | `conflict` |

## 三、下游约束

1. **B / D9 归因**：`evidence_strength ∈ {weak, none, conflict}` **默认不参与跨文档数值矛盾比较**；参与须有强锚佐证并标注强度。
2. **陈的页面**：显示强度徽章；`none`/`conflict` 走证据不足/冲突态，不得显示为矛盾。
3. **张的解析侧**：块级锚升 cell 级可提升强度，工作量为受益项、非阻塞。
4. **魏**：`audit_fang_d7.mjs` 保留为审计层，不回写信封。

## 四、锁定项（改动需重新裁决）

不改 `value` / Gold / 封存集；无锚与冲突才降级；弱锚及以下不进矛盾比较。

## 五、校验

```powershell
node evaluation/integration/check-strength-tier.mjs --audit <魏的审计输出> --json evaluation/integration/strength-tier-check.json
```

硬校验两条锁定项：①任何改动不得改 `value`；②只有 `none`/`conflict` 允许 `status` 降级。违反即 FAIL。

魏未回传强度分布时，工具会提示 `unknown`，此时 `none`/`conflict` 清单仍待定（属可修订项，不阻塞开工）。
