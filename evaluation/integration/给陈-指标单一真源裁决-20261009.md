# 给陈：指标单一真源裁决（2026-10-09）

发件：宗（评测侧）｜正式裁决：`evaluation/integration/指标单一真源裁决-20261009.md`｜锚点：`权威批次锚点.json`

## 一、你发现的是**目前最大的评审风险**

D19 对账：页面（`data/`，30 份 09-28~10-02）与材料（`data_unified/`，32 份 10-04~10-07）**零重叠**，导致：

| 来源 | 数字 | 样本 |
|---|---|---|
| 页面 | extracted=**71.53%**（fields_total=548） | 旧 `data/` |
| 材料 | **437/437**（分母 615） | `data_unified/` |

**评审一对照就认为数字对不上。** 你指出的关键点我也认可：`metrics.js` 的"实算、无估算"是真的，但**没标注是哪一批**——实算旧数据与实算当前数据在页面上长得一样。

## 二、裁决：页面**默认视图必须切到权威批次**

最小改动（加一句"数据来自旧批次"）**能过检查但没解决问题**——两个数还在同屏。**单一真源**才是根治：页面上只有一个批次、一个口径、一个数字；历史批次只能作**显式命名的对照**，且不得与当前数字同屏。

### 权威批次唯一锚点

```
定义：权威批次 = 魏 D11 首测冻结批次 = 30 核心文档 + 1 扫描降级 = 31 份
docs          = 31
anchor_sha256 = 381c760fa07b2dc3a8256282e23009bce4b79445fdc7f4f4280168af6c90cef0
```

算法：31 个 json 按文件名升序，逐份 sha256，拼 `文件名:哈希` 以换行连接，再取 sha256。

**⚠ 注意**：`evaluation/D11/firsttest-envelopes/` 目录内实际有 **32 个 json**——多出的一份是 `DEMO-EQC-HL-0930`（我为补 D10 集成用例加的**演示补料**），**不计入权威批次，锚点已排除**。你在做守卫时请按同样口径排除。

## 三、要求（分两级）

### FAIL 级（R1–R4，均可机器判定）

| # | 要求 |
|---|---|
| **R1** | 页面**默认**读权威批次；旧 `data/` 只能作显式命名的历史对照，不作默认 |
| **R2** | 任何展示的指标必须带**批次标识**：批次 id + 日期 + `anchor_sha256` 前 12 位 |
| **R3** | **不同批次的数字禁止并列引用**（同屏/同段/同表） |
| **R4** | 同一 `file_sha256` 的多次抽取必须标注为**同源变体**（P0-01：旧 1 事件 vs 新 3 事件），不得显示为两个独立 case |

### WARN 级（R5–R6，涉及语义标注）

| # | 要求 |
|---|---|
| **R5** | 合成输入（承担 D4 角色的 `D3-PLD-00x.txt`）必须显式标注"**合成样例**"，不得与真 PDF 混同 |
| **R6** | 页面与材料字段规模不同时，引用必须分别带来源 |

## 四、对你守卫脚本的要求

`demo/_data_source_check.js` 现为 10 PASS / 0 FAIL / **4 WARN**，升级为**分级**：

- **R1–R4 → FAIL**（默认数据源路径、批次标识存在性、同屏批次唯一性、`file_sha256` 重复项是否标注）
- **R5–R6 → WARN**
- **保留 `--strict`**，封版前一次性把 WARN 翻 FAIL

**关于"常驻刷红"的顾虑**：R1–R4 判 FAIL **不会**造成这个后果——这四条是**代码/展示层可立即修复的，修完即绿**。你当初把"重叠度 0"判 WARN 是对的（那时口径未定）；**现在口径已定，应升级为 FAIL**。

## 五、我的验收标准（我会独立复核这四条）

1. 页面**默认**加载后，指标来源能对上 `anchor_sha256`；
2. 页面任意指标旁可见**批次标识**（id + 日期 + 哈希前 12 位）；
3. 同屏不存在两个不同批次的数字；
4. 存在同 `file_sha256` 多份输出时，页面标注了同源变体关系。

## 六、时限

- **R1–R4**：下一次封版前必须绿；
- **R5–R6**：可由 `--strict` 门禁覆盖，不阻塞封版。

## 七、附：我这边的勘误

本裁决初稿把权威批次记为 31 份、但锚点实际按目录**全部 32 份**算过一版（我漏排除 DEMO）。已更正并登记勘误——**责任在评测侧**。这也是为什么我在锚点里写死了口径：**含糊的"权威批次"等于没有权威批次。**
