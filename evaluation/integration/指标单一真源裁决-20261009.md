# 指标单一真源裁决（评测侧）

日期：2026-10-09｜裁决人：宗（评测侧）｜触发：陈 `b2a0bcb8` D19 数据源对账

## 一、事实（陈的对账结果，我复核认可）

| 目录 | 份数 | 日期 | 谁在读 |
|---|---|---|---|
| `data/` | 30 | 09-28~10-02 | **页面下拉 + `/api/metrics`** |
| `data_unified/` | 32 | 10-04~10-07 | 重测脚本（与魏 D11 冻结批次**逐字节 31/31 一致**） |

**两目录文件名零重叠，权威批次在页面上完全不可见。**

后果：

| 来源 | 数字 | 样本 |
|---|---|---|
| 页面 | datasets=31、fields_total=548、extracted=**71.53%** | 旧 `data/` |
| 材料 | **437/437**、字段分母 615 | `data_unified/` |

**两个数字常被并列引用，却出自不同样本。** `metrics.js` 的"实算、无估算"是真的，但**未标注批次**——实算旧数据与实算当前数据在页面上长得一样。

## 二、裁决

### 主裁决：**页面默认视图必须切换为权威批次**

指标口径的**单一真源**优先于一切展示便利。页面不得默认展示非权威批次的计算结果。

### 权威批次的唯一定义

**权威批次 = 魏 D11 首测冻结批次**（`weiwenyu@bc67ccd8` → `evaluation/D11/firsttest-envelopes/` 中的 **31 份 = 30 核心文档 + 1 扫描降级**）。目录内另有 1 份 `DEMO-EQC-HL-0930`（演示补料），**不计入权威批次**，锚点计算已排除。

**唯一锚点（可核验）**：

\\\
docs            = 31（30 核心 + 1 扫描降级；目录内另有 1 份 DEMO 演示补料不计入）
anchor_sha256   = 381c760fa07b2dc3a8256282e23009bce4b79445fdc7f4f4280168af6c90cef0
\\\

锚点算法：对该目录下 31 个 json 按**文件名升序**，逐份计算 `sha256`，拼成 `文件名:哈希` 行、以 `\n` 连接，再取 `sha256`。任何引用"权威批次"的地方都必须能对上这个值。

### 四条强制要求

| # | 要求 | 级别 |
|---|---|---|
| **R1** | 页面**默认视图**读权威批次；旧 `data/` 只能作为**显式命名的历史对照**，且不得作为默认 | **FAIL** |
| **R2** | 任何展示的指标必须带**批次标识**：批次 id + 日期 + `anchor_sha256` 前 12 位 | **FAIL** |
| **R3** | **不同批次的数字禁止并列引用**（同屏、同段、同表） | **FAIL** |
| **R4** | 同一 `file_sha256` 的多次抽取必须在页面标注为**同源变体**（如 P0-01：旧 1 事件 vs 新 3 事件），不得显示为两个独立 case | **FAIL** |

### 两条标注要求

| # | 要求 | 级别 |
|---|---|---|
| **R5** | 合成输入（如承担 D4 角色的 `D3-PLD-00x.txt`）必须显式标注"**合成样例**"，不得与真 PDF 混同 | WARN |
| **R6** | 页面与材料的字段规模（分母）若不同，引用时必须分别带来源 | WARN |

## 三、对陈的守卫脚本要求

`demo/_data_source_check.js` 现有 10 PASS / 0 FAIL / **4 WARN**。升级为**分级**：

- **R1–R4 → FAIL**（可机器判定：默认数据源路径、批次标识存在性、同屏批次唯一性、`file_sha256` 重复项是否标注）
- **R5–R6 → WARN**（涉及语义标注，机器只能判"是否缺标注"）
- **保留 `--strict`** 把所有 WARN 翻成 FAIL，供封版前一次性收紧

**特别说明**：R1–R4 判 FAIL **不会**让每日回归"常驻刷红"——因为这四条是**代码/展示层可立即修复的**，修完即绿；陈原先把"重叠度 0"判 WARN 是因为那时口径未定，**现在口径已定，应升级为 FAIL**。

## 四、我的验收标准

我按以下四条独立复核，全部通过才算 R1–R4 闭环：

1. 页面**默认**加载后，其指标来源 = 权威批次（`anchor_sha256` 对得上）；
2. 页面任意指标旁能看到**批次标识**（id + 日期 + 哈希前 12 位）；
3. 同屏不存在两个不同批次的数字；
4. 存在同 `file_sha256` 多份输出时，页面标注同源变体关系。

## 六、为什么这是"最完美"而不是"最小改动"

最小改动是"在页面上加一句'本页数据来自旧批次'"——**能过检查，但没解决问题**：评审仍然看到 71.53% 与 437/437 两个数并存。

**单一真源**才是根治：页面上只有**一个批次、一个口径、一个数字**；历史批次作为**对照**存在，必须显式命名、且不能与当前数字同屏。
