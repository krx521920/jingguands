## 演示 2：批量上传闭环（D6 交付）

1. 左栏点击虚线框（或整批拖入），可一次选**多个** `.json` 事件信封 → 上传前先逐文件列出占位条目（"等待上传"），上传中顶部出现**总进度条**（真实字节级进度）；
2. 上传完成显示**批次报告**：
   - 摘要徽章：`批次 <batch_id>：N/M 成功，X 失败`；
   - **失败列表置顶（红色）**：坏 JSON / 非 JSON / 缺 events 的文件**每一条都在报告里，绝不消失**，附明确失败原因（如"JSON 解析失败：…"）；
   - 成功文件：`文件名 → 数据集 <dataset>（N 事件）`，同名再传自动改名 `-2/-3`（不覆盖既有数据集）；
   - **⬇ 下载上传日志**：JSONL 逐文件一行（含失败原因与 batch_id），可直接人工排查；
3. **真实闭环**：首个成功文件自动进下拉并加载——栏二结果、栏三证据、股权对比块同源同款生效，无需任何手动操作；
4. **口径**：页面做的是"信封校验 + 过桥干跑 + 落数据集"，不做 PDF 解析——解析仍在张智博 finstruct 链路完成，页面消费成品 run（见演示 4）。

## 演示 8：切换真实接口（remote 模式）

```powershell
# ① 本地假上游（模拟魏的接口，零依赖；联调时换成真 REMOTE_API_URL 即可）
node demo/mock_upstream.js                       # → http://127.0.0.1:9000/result

# ② remote 模式起页面（另开一个终端）
$env:PORT = "8643"
$env:DATA_SOURCE = "remote"
$env:REMOTE_API_URL = "http://127.0.0.1:9000/result"
node server.js
```

浏览器打开 `http://127.0.0.1:8643`（**8643 端口**，与 mock 的 8642 并存互不影响）。前端零改动——上游返回契约对象或上游格式（魏事件信封 v0.3）均自动过桥，`data_mode: "real"` 时横幅消失、徽章变绿。接口实证：`/api/result?dataset=wei_real_pledge_0197` → `data_mode=real`，`bridge.from=wei-event-envelope-v0.3`。
