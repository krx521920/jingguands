## 0. 怎么用这张表

- **一事项一编号**：§1 对照表是唯一真源；`D11-*` / `D12-*` / `Nxx` 是历史别名，只在溯源时用，**不再新增**。
- **四态状态机**：`未开始` ｜ `进行中` ｜ `阻塞` ｜ `已完成`。不用 ✅/⏸/⛔ 混排（v1 的毛病）。
- **每条必带验收判据**：写不出验收判据的条目不许进表。
- **纪律不变**：队友责任项**只登记、不代答、不代承诺**；任何数字引用一律带分子/分母。

## 7. 环境坑（本轮实证）

1. **沙箱拦 `~/.ssh/config` 读取** ⇒ git 读不到「`github.com` → `ssh.github.com:443`」规则，回落默认 **22 端口**报 `Connection timed out`。**与梯子无关**，`git fetch/push` 需绕过沙箱执行。
2. **过期锁 `.git/dsh-lefthook-install.lock`** 会让 `pnpm install` 的 postinstall 失败 ⇒ `pnpm run typecheck` 连带失败 ⇒ pre-push 报「假失败」。删掉该锁即可。
3. **`pre-push` 的 typecheck 是仓库级闸门**，检查整个 monorepo（不只我方 `workspace/cjh/`）。判断「是不是我引入的」要看 `git diff <远端sha> HEAD -- <报错路径>` 是否为空，而不是看错误数量。
4. **`pnpm install` 会漂移 `pnpm-lock.yaml`**（`@types/ws` 8.18.1→8.18.2 等）⇒ 跑完 pnpm 相关命令后**必须检查 lockfile 是否被改**，是则 `git checkout --` 还原。
5. **`git rev-list --objects --all` 在本仓极慢**（部分克隆触发懒加载，420s 跑不完）⇒ 统计体积一律用 `git ls-tree -r -l <ref>`。
6. **本仓是 `blob:none` 部分克隆**：新 clone 不下载全量 blob；HEAD 被跟踪树 360.6 MB / 17,244 文件（`.json` 251 MB＝活数据）；`git rev-list --count HEAD` = 8；共 27 个引用（26 远端分支 + 3 tag）⇒ **任何历史重写都会让全员 clone 与交付 tag 失效，禁**。
