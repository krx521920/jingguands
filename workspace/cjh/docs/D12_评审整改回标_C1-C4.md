## C1｜Web/CLI：同意正式标「未覆盖」

### 采纳宗的意见，且理由比原文更硬

宗建议选②（"没有可核验载体就不算通过"）。核查后**同意**，并补三条硬证据：

1. **该字段是被测方手填的布尔常量**，校验脚本不验任何实际对照数据：
   ```js
   // evaluation/D10/check-integration.mjs:32
   if (ct.web_cli_same_result !== true) notes.push('WEB_CLI_MISMATCH');
   ```
2. **宗与魏自己已把定义写明是「同源」而非「对照」**：
   - 宗 `cache-evidence.json:27`：*"同一次运行的信封 JSON 为唯一事实源：Web（陈页面）与 CLI 消费同一文件"*
   - 魏 `weiwenyu-bundle.json`：*"CLI 产物（信封 JSON）为唯一事实源，Web（陈页面）读取同一文件"*

   同一文件被两个消费者读取 —— **它把"抽取差异"这一维度整个消掉了**，剩下的只是幂等性冒烟检查。
3. **仓库里 FAIL 与 PASS 两份成绩单并存**，正是语境证据：
   - `d10-score.json` = **FAIL 0/10**（全带 `WEB_CLI_MISMATCH`）
   - `score-rebuilt.json` = **PASS 10/10**

   差别只是 rebuilt 把 `run_id` 从 null 填上、三个布尔从 false 填 true —— **补的是 cache 块声明，不是对照数据**。

### 页面侧处置（已完成，不只是"同意"）

|---|---|
| 缓存面板第三项 | 由绿色 ✔「Web/CLI 一致」→ 中性「**同源消费，非独立对照 —— 判未覆盖**」 |
| 10 张 case 卡徽标 | 由「Web/CLI 一致 ✔」→ 灰色虚线「**Web/CLI 未覆盖**」 |

### ★ 一条自曝：我在写这套机制时踩了 D10 的同款坑

第一版 `parity()` 写的是"无差异即通过"，结果 **30 例全失败却输出 `verdict:"pass"`** —— 与 `d10-score.json`(FAIL 0/10) → `score-rebuilt.json`(PASS 10/10) 是**完全同一款漏洞**："没跑成"被算成"跑成了且一致"。

| 铁律 | 内容 |
|---|---|

| 空清单拒判 | 显式传 `cases=[]` ⇒ `not_covered`（区别于"未传"跑全量） |

另：**未配置 provider 一律 `available=false` + 给可执行原因，绝不静默回落到 file**（静默回落＝假装跑过）。
