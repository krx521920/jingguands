## 二、D3 做成了什么

### 1. 多层表头绑定（核心）

真实质押公告的表格有**跨列的分组表头**。以 `pledge-001` 第 1 页表 2 为例：

```
r1 | 股东名称 | … | 已质押股份情况        | ·  | 未质押股份情况        | ·
r2 | ·      | … | 已质押股份限售和冻结… | 占已质押股份比例（%） | 未质押股份限售和冻结数量（股） | 占未质押股份比例（%）
```

r1 的「已质押股份情况」是**跨 2 列的合并单元格**，r2 才是它的子列。
D3 把它逐级拼成完整列名，挂在每个数据单元格上：

| 单元格 | 值 | `header_path` |
| --- | --- | --- |
| `r3c7` | 23.62% | 占公司总股本比例（%） |
| `r3c8` | 50,350,000 | **已质押股份情况**/已质押股份限售和冻结、标记数量（股） |
| `r3c9` | 100.00% | **已质押股份情况**/占已质押股份比例（%） |
| `r3c10` | 15,227,852 | **未质押股份情况**/未质押股份限售和冻结数量（股） |
| `r3c11` | 41.06% | **未质押股份情况**/占未质押股份比例（%） |

**为什么这值钱**：不拼前缀的话，`r3c9` 和 `r3c11` 的列名分别只是「占已质押股份比例（%）」与「占未质押股份比例（%）」——都带括号、都指比例，抽取层无法判断归属哪一组。拼完之后语义才完整，**这才是「字段与页面区域绑定」能落地的前提**。

实现要点：
- `rowspan` / `colspan` 由单元格 box 与网格带求交得出（合并单元格必须知道跨度，否则子列取不到祖父级表头）
- 表头行判定：前导行中「值型单元格 ≤1」即表头行，上限 3 行
- 列数 < 3 的窄表**不判表头** —— 那种表多是「字段名: 值」的竖排键值表（`equity-change-001` 的两张就是），按网格表头处理会把每行都误当表头

### 2. `cell_ref` 契约对齐

魏文宇的 `run_extract.mjs` 读的是 `block.table_ref.cell_ref`，而 D2 输出的是 `cell_id`——
**两边名字对不上，他的链路会把表格单元格出处静默丢成 `null`，不报错也不告警**。
D3 按契约输出 `cell_ref`（1 基，形如 `r2c3`），`cell_id` 保留为全文档唯一的内部键。

### 3. 跨页续表标注

中文公告的表格常跨页断开，断点有两种形态，**必须分开处理**：

| 形态 | 表现 | 处理 |
| --- | --- | --- |
| **行边界断开** | 上页末行完整，下页首行是新数据行 | 只标 `continued_from`，行本身不用动 |
| **单元格内断开** | 下页首行只有一列有内容、其余列空 | 除 `continued_from` 外，还给碎片单元格标 `continues` 指回上页同列 |

实测 `pledge-001` 属于第二种，股东名称被页边界切成两半：

```
上页 r4c1 = 山东省国际信托股份
下页 r1c1 = 有限公司－山东信托·传字6364号财富传承财产信托
            ↑ 标 continues → 指回 r4c1
```

**只取下半截当股东名称就是错的**，两半拼起来才是完整的
「山东省国际信托股份有限公司－山东信托·传字6364号财富传承财产信托」。

`equity-change-001` 也有跨页续表，但断在行边界上 —— 它只标 `continued_from`，
**不标碎片**（否则消费方会把两个独立的值错误地拼在一起）。回归用例同时锁了这两种情形。

### 4. 禁止事后按数字搜索补出处

出处是**解析时随字符一起生成**的：每个字符在聚类阶段就归属到某个块或某个单元格，
`region` 是该块字符的外接矩形，从不靠字段值回查。

这条团队规则由三组回归用例把它钉死，而不是靠声明：

1. **同页内相同文字必须得到不同出处。** 「拿值回文档搜第一次出现」这种反查法有个必然特征：
   相同的值会指向同一个位置。而我的 region 来自字符位置，所以同页同文字必然位置不同。
   实测三份公告共 **14 组**同页重复文字，region 撞车 **0 组**。
   （判据限定同页：页眉会在每页以完全相同坐标重复，跨页比会误判。）
2. **出处覆盖 100% 的块。** 反查法只会给它抽到的字段产生出处；解析法对每个块统一产生。
3. **区域自洽。** `tools/check_evidence.py` 把 `region` 内的字符重新取出来拼一遍，
   必须等于块声称的文字 —— 三份公告 100% 通过（127 / 61 / 75 块）。

## 三、D3 修掉的两个真 bug

### bug 1：`cell_id` 跨表撞车（隐蔽，D2 那个 94/95 的根因）

`cell_id` 原先是**表内序号**，两张表各自从 `c001` 编号。`pledge-001` 第 1 页有两张表，
实测 t002 的 `c001–c035` 直接覆盖了 t001 的同名单元格，导致 **t001 第 1–8 列的字符全部认领失败**、
掉进文本乱序的兜底块。

因为它是 dict 静默覆盖，**不抛异常、不给警告**，只表现为「表头文字莫名其妙变成乱序」。
现改为带 `table_id` 前缀、全文档唯一。

| | 修前 | 修后 |
| --- | --- | --- |
| p1 单元格块 | 53（18+35） | **88（全部）** |
| p1 兜底块 | 5（文本乱序） | **0** |
| t001 表头列 | 3 / 11 | **11 / 11** |

### bug 2：行号推导取错行

原先用 pdfplumber 的 `t.rows[].bbox` 判断「落在第几行」，但它在**纵向合并时会互相重叠**
（实测 `rows[1]` 与 `rows[2]` 的 y 区间交叠），取首个命中区间会把第 2 行误判成第 1 行，
于是 53 个单元格只推出 20 个唯一 `cell_ref`。

改为从**单元格自身坐标**推网格（相异上边界即行、相异左边界即列），全部表零撞车。

## 六、给下游的接口

每个表格单元格块带 `table_ref`：

```json
"table_ref": {
  "table_id": "d44e95085_p001_t001",
  "cell_id": "d44e95085_p001_t001_c039",
  "cell_ref": "r1c8",
  "row": 0, "col": 7, "rowspan": 1, "colspan": 1,
  "header_path": "已质押股份情况/已质押股份限售和冻结、标记数量（股）"
}
```

续表相关：

```json
"tables": [{ "table_id": "…_p002_t001", "continued_from": "…_p001_t002" }]
```

```json
"table_ref": {
  "cell_ref": "r1c1",
  "continues": { "table_id": "…_p001_t002", "cell_ref": "r4c1", "block_id": "…_b00090" }
}
```

`continues` 非空表示这个单元格是碎片，**必须先与指回的那一格拼接再取值**。

映射到两份契约：
- **魏文宇**（抽取契约）：`table_id` → `provenance.table_id`，`cell_ref` → `provenance.cell_ref`
- **宗博文**（评测证据）：`table_id` → `table`，`cell_ref` → `cell`

`handoff.field_aliases` 里有完整的三方对照表。

### 5. 分栏检测

中文年报/招股书常用双栏排版。按单栏读会逐行左右交错，得到乱序句子。

难点在于**误报**：单栏页面上居中的标题同样留下大片 x 空白；更糟的是表格 ——
一张 11 列的质押表天然一堆列间空白带，按整页扫描时 pledge-001 p1 会报出 3 条假栏缝。

两条判据把它压住了：
1. **按文本行统计，不按整页统计** —— 栏缝要在绝大多数文本行里都空着。居中标题只占 1 行。
2. **先排除表格内字符** —— 页级栏缝只作用于正文流，表格内部有它自己的列坐标。

阅读顺序按「**整幅行分段、段内逐栏**」排：跨栏缝且中缝里有字符的行是整幅元素
（标题、元信息），独占一段排在最前；其余行按中缝拆开、各归其栏。
实测两份栏 fixture 的顺序是「标题 → 元信息 → 左栏 → 右栏」，且无块内交错。
四份单栏文档共 14 页，`columns` 全部为空、**逐块内容零变化**。

## 七、已知边界

1. **续表只打标、不自动拼接**。这是刻意的：该怎么拼取决于语义
   （同一个单元格的延续 vs 恰好同列的两个不同值），解析层不替下游决定。
   消费方要读 `table_ref.continues` 自己拼。
2. **无框表格**（纯 stream 模式，没有绘制线）检不出，`find_tables()` 依赖线框。
3. **表头行判定是启发式**：若某张表的表头里含 ≥2 个纯数字单元格，会被误判成数据行。
   中文公告的质押表未出现这种情况，但换事件类型时需要复核。
4. **`text_raw` 的跨行西文分叉**在真实公告里仍未触发（三份都是中文），
   机制由构造用例单独保证。
5. **分栏检测只处理竖向栏缝**，不处理同栏内的嵌套分栏；表格横跨栏缝时
   不切栏（那是整幅元素，硬切会让表格与两栏正文交错）并给出警告。
6. **双栏正例是合成 fixture**（`tests/fixtures/twocol_synthetic.pdf`）——
   现有四份真实文档全是单栏，没有真实正例可用。
