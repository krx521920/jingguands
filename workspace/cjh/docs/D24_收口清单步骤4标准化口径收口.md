## 一、卡片拆两项（核心要求）

D17 裁定要求把「标准化率」拆成两个不可互溶的指标，**且目标 98% 只挂正确率**：

| 卡片 key | 名称 | 值 | 分子/分母 | 目标 | 上屏徽标 |
|---|---|---|---|---|---|
| `standardized_pct` | 标准化覆盖率 | 100% | 229/ 229 | **无** | 无对标目标 |
| `standardized_accuracy_pct` | 标准化正确率 | 100% | 229 / 229 | **98** | 达标 +2 |
| `extracted_pct` | 字段抽取覆盖率 | 72.11% | 437 / 606 | **无** | 无对标目标 |
| `provenance_hit` | 出处命中率 | 100% | 241 / 241 | 95 | 达标 +5 |

口径定义（严格按裁定原文）：

- **标准化覆盖率**＝ `standardized=true` 的**非 text 有值字段** / **非 text 有值字段**。
  分母**不含**弃权字段、不含 `unit: text` 字段。→ 229 / 229
- **标准化正确率**＝ 非 text 有值且有 Gold 期望的字段中，`value` 与 Gold 规范值一致的比例。
  值层承载：`value` 就是规范化后的取值，值层一致即标准化正确。→ 229 / 229

**为什么覆盖率不能挂 98**：覆盖率的分母不含弃权，它回答"该标准化的有没有标准化"，
不是"抽得对不对"。把准确率类考核线挂在它上面，等于用错口径宣布达标。
门 `check-metrics-caliber.mjs` 的 R1 规则正是查这个（概念未声明目标、卡片却挂了目标）。

## 五、顺手修掉的两个真实缺陷

### 1. 无目标项会被谎报成"达标"

原判定 `status: value >= target`。当 `target` 为 `null` 时 `value >= null` **恒为 true** ——
两个覆盖率会被渲染成绿色"达标"，比缺目标更糟（用错口径宣布达标）。
现改为 `no_target` 独立状态：中性色 + 徽标「无对标目标」+ 目标行显示说明而非 `目标 null%　差距 NaN`。

### 2. 试跑会污染正典产物（本次真实踩到）

我用 `SNAP_DIR=…_snapshots/…` 试跑出处核验，脚本直接把正典产物
`demo/_evidence_quote_real.json` 从 **241/241 覆盖成 192/214** —— 页面的数静默换了口径。
已加两道闸：
- `SNAP_DIR` 非默认时**拒绝写正典产物**，提示只走console；
- 需留档必须显式 `--out <副本路径>`。
顺带修掉自己引入的第二个 bug：提示文字被追加进 JSON 文件，导致下游 `JSON.parse` 全部失败
（产物是数据源，掺一句话就毁掉）—— **提示只能走控制台，绝不进JSON**。

现产物已恢复正典 241/241，三向验证通过（拒写 / 产物不受影响 / `--out` 副本可留）。
