## 3. JS 模块接口（页面侧真实调用面）

### 3.1 `bridge/extractor.js` — 抽取引擎适配层

```js
module.exports = { extract, parity, describeEngines, defaultEngine, diffEnvelopes, evKey, PROVIDERS };
```

| 函数 | 签名 | 返回 | 契约要点 |
|---|---|---|---|
| `extract` | `async (caseId, engineId?) => {ok:true, engine, data, run_meta}` \| `{ok:false, engine, reason}` | 恒 `run_meta.contract_version="0.3"`；`data` 已过 `toContract()` |
| `describeEngines` | `() => Engine[]` | 每项含 `caps{reruns_extraction, needs_pdf, same_file_as_peer, label}`，页面据此渲染 |
| `defaultEngine` | `() => "cli"\|"http"\|"file"` | 有 live 引擎取第一个，否则 `file` |
| `parity` | `async (caseIds[], {a,b}) => {verdict, …}` | **同源即拒判**：两侧 `same_file_as_peer` ⇒ `not_covered`。判定全部委托 `parity_criteria.js`，返回带 `criteria_version`＋五级 `s0..s3`＋`mismatch_detail[].failed_levels` |
| `diffEnvelopes` | `(envA, envB) => {pairs, only_a[], only_b[], same, compared, diff[]}` | 按 `evKey` 配对（**禁用 event_id/序号**） |
| `evKey` | `(ev) => "type\|k1\|k2\|k3"` | pledge: pledgor+pledgee+direction／equity_change: holder+direction／award_contract: bidder+project_name |

**三个 provider 的能力画像（诚实声明，不可粉饰）**

| provider | kind | `reruns_extraction` | `same_file_as_peer` | `available()` 条件 |
|---|---|---|---|---|
| `file` | `prebuilt` | `false` | `true` | 恒真（`data/` 常驻） |
| `cli` | `live` | `true` | `false` | 入口脚本存在 ∧ `EXTRACT_CLI_PARSE_DIR`/`TXT_DIR` 目录存在 ∧ **有 LLM 密钥** |
| `http` | `live` | `true` | `false` | 设了 `EXTRACT_HTTP_URL` |

**cli provider 对齐魏文宇 `run_extract.mjs` 的真实契约（`weiwenyu@93c8ae28`）**

```
调用：node scripts/jingguan/run_extract.mjs (--parse <parse.json> | --input <txt>) --out-dir <dir> --event-type <T>
输入：解析 JSON / .txt —— 不是 PDF（页面侧不做 PDF 解析）
输出：落盘 <out-dir>/events.json —— 不在 stdout，必须读文件
守卫：exit≠0 拒判｜events.json 缺失拒判｜非合法 JSON 拒判｜run_meta.is_mock=true 二次拒判
顺序：mock 判定必须在事件类型推断之前（否则报「无法推断事件类型」，指向错误原因）
事件类型映射：pledge|PLD|D4 ／ equity_change|equity|EQC|share_change|D5 ／ award_contract|award|AWD|D6（大小写无关）
覆盖缺口：bank_guarantee 不在魏 registry.mjs（只有 pledge/equity_change/award_contract）⇒ `unsupported_by_engine`，须魏扩 registry
环境变量：EXTRACT_CLI_CMD / EXTRACT_CLI_REPO / EXTRACT_CLI_PARSE_DIR / EXTRACT_CLI_TXT_DIR /
         EXTRACT_CLI_OUT_DIR / EXTRACT_CLI_TIMEOUT(180000) / EXTRACT_CLI_EVENT_TYPE_MAP /
         JINGGUAN_LLM_API_KEY 或 DEEPSEEK_API_KEY
★ 刻意不加 --mock：无密钥已在 available() 拒判，此处加 mock 等于用假数据顶替真跑
★ 密钥来源：`.env`（page_prototype/.env，不入库），由本文件顶部 `loadDotEnv()` 读入 process.env，
   **只在变量尚未存在时注入**（真机/CI 环境变量优先，不会被本机旧值覆盖）；找不到 .env 静默跳过，
   此时 available() 仍因缺密钥而显式拒判 —— 缺文件是队友 clone 的常态，不是错误。
```

**http provider（预留）**：`GET <EXTRACT_HTTP_URL>?case_id=<id>` → 期望返回信封 JSON；不可达/非 JSON 均拒判。

### 3.2 `bridge/upstream_bridge.js` — 转接口

```js
module.exports = { toContract, isUpstream, isWeiEnvelope, checkIntegrity, DENOMINATOR_TEXT, SOURCE_TYPE_TEXT, DIRECTION_TEXT, MISSING_REASON_TEXT };
```

| 函数 | 作用 |
|---|---|
| `toContract(obj)` | **唯一入口**，识别顺序：魏 v0.3 信封 → 契约对象透传 → 方口径记录 → 未知原样透传留痕（`bridge.passthrough=true`） |
| `isWeiEnvelope` | 判据：`schema_version==="0.3"` ∧ `events[]` ∧ `typeof is_mock==="boolean"` |
| `checkIntegrity(events, evidences)` | `{ok, issues[]}`，issue=`{level:error\|warn, where, what}` |

`checkIntegrity` 六项检查：有值无出处（error）／引用不存在 evidence（error）／`source_type=cell` 缺 `table_id|cell_ref`（error，红线）／`source_type=table` 兜底块（warn）／所有出处均为扫描降级块（warn）／`scan_region+degraded` 缺 `missing_reason`（warn）。

魏 6 态 → `status_override` 映射：`extracted→无 override`／`needs_review→pending_review`／`unreadable→unreadable`／`not_disclosed→not_disclosed`／`not_applicable→not_applicable`／`not_mentioned→not_mentioned`。
direction 契约守卫：`equity_change` 只允许 `increase|decrease`、`pledge` 只允许 `pledge|release`（v0.4 宗裁决）；非英文枚举**不做静默兜底**，记 `bridge.notes` 并标 `pending_review`，让违规可见。

### 3.3 `bridge/metrics_registry.js` — 指标单一真源

```js
module.exports = { CATEGORIES, STATUS, list, get, byCategory, notCovered, coverageStatement, fingerprint, REGISTRY, MEASURED };
```

四类**不可互溶**（`CATEGORIES` 里写死了 `denominator_rule` 与 `must_not_mix`）：

| 类别 | 分母规则 | 禁止混用 |
|---|---|---|
| `accuracy` 准确率 | 有 Gold 人工标注的字段 | 不可与覆盖率混用 |
| `coverage` 覆盖率 | 契约注册表要求抽取的字段全集（含弃权） | 抽不出 ≠ 抽错 |
| `evidence` 出处命中率 | 已产出且带锚点的字段 | 带 block_id ≠ 能回跳原文 |
| `compliance` 格式合规 | 已标注 `standardized` 的字段 | 无目标值不虚构 |

三状态：`measured`（实测出数）／`unverified`（有分母无对照物，不可当验收依据）／`not_covered`（**未测，禁止按目标值填充**）。

14 项指标：`field_accuracy`／`wrong_fill_rate`（准确率）｜`field_coverage`／`abstain_correct`（覆盖率）｜`evidence_hit`／`anchor_presence`／`anchor_table_ref`／`block_region_selfconsistency`（出处）｜`standardized_rate`（合规）｜`cross_doc_match`／`multi_doc_conflict`／`integration_pass`／`scan_degrade`／`perf_20page`。

`fingerprint()` 返回 `{inputs:{page_data, unified_batch}, primary, combined_sha256}` —— **材料引用成绩必须同时带 `input_fingerprint` 与 `source_script`**，否则不可复现、不可追责。
动态真源：`evidence_hit` 读 `demo/_evidence_quote_real.json`，快照撤走即自动退回 `not_covered`（已实测 8/6 ⇄ 7/7）。

### 3.5 `bridge/parity_report.js` — 对照报告读取

```js
module.exports = { loadReport, badgeOf, LAYER_PHRASES, REPORT };  // REPORT = demo/_parity_real.json
```

| 层 | 证明 | **不证明** |
|---|---|---|
| L1 文件哈希 | 两侧是不是同一份文件（哈希同 ⇒ 同源，其后各层"一致"不作证据） | 不证明任何抽取质量 |
| L2 跨批逐字段 | 两批离线产物在同一文档上的字段取值是否稳定 | **不证明 Web/CLI 一致**——两侧都不是 Web/CLI |
| L3 导出字节 | 导出链路序列化稳定（无编码/BOM/列序漂移） | **不证明抽取一致性**——同源同函数，这是幂等性 |

`badgeOf(verdict)`：`consistent|distinct|idempotent → ✓ 已测·通过`；`divergent|same_source_partial → ✗ 已测·有差异`；`not_covered|partial → — 未测`。
报告文件缺失 ⇒ `not_covered` + 打印重跑命令，**不回退到任何"通过"表述**。

## 5. 端到端数据流（含每跳的契约）

```
① PDF ──张智博 finstruct.parse──► parse.json {blocks[], text, page}
                              └──► evidence.v0.9 {covers, degraded, missing_reason}
②  parse.json ──魏 run_extract.mjs──► events.json（信封 v0.3）
        argv: --parse/--input --out-dir --event-type ；run_meta.is_mock 必带
③  events.json ──本页 toContract()──► 契约 v0.3
        is_mock→data_mode｜6 态→status_override｜provenance[]→evidences[]｜unit 枚举→中文
④  契约 ──/api/result──► 渲染器（results + evidences 联动定位）
                 ──/api/export──► JSON / CSV 18 列（同源同桥）
                 ──/api/parity──► 逐字段 diff（evKey 配对）
⑤  契约 ──metrics.js/registry──► /api/metrics ──► 图表页（4 类 14 项，分列不合并）
⑥  两批信封 ──_parity_real.js──► _parity_real.json ──parity_report──► /api/parity/real ──► 图表页对照三层
⑦  .check.json + provenance + b_report + d10/* ──server 装配──► /api/verify｜pairs｜integration
```

**每一跳都必须携带的东西**（缺了在下游就是"未测"而不是"通过"）：

| 跳 | 必带 | 缺了会怎样 |
|---|---|---|
| ②→③ | `is_mock` | 缺则无法判定是否 mock，`cli` provider 拒判 |
| ③→④ | `evidence_id`（可多值 `evidence_ids`） | 缺则 `checkIntegrity` 报 error，页面黄/红条 |
| ④→⑤ | `source_file.file_id`(sha256) | 按 `case_id`/`file_name` 配对 ⇒ 假失配（Gold 跨批次沿用旧名） |
| ⑤→⑥ | `input_fingerprint` + `source_script` | 引用成绩不可复现、不可追责 |

## 6. 关键设计决策与其代价（为什么这样写）

| 决策 | 原因 | 代价 |
|---|---|---|
| `extract()` 单一入口，result/export/parity 共用 | 免得三处各判一次引擎，口径分叉 | `file` 引擎被导出强制使用（导出必须与页面所见同源） |
| 同源即 `not_covered` | D10 `web_cli_same_result` 造假的根因 | Web/CLI 面板长期显示"未测"，不好看但真实 |
| `available()` 硬门槛（无密钥即拒判） | 防止"未接通静默回落 file＝假装跑过" | 演示前必须配好密钥与输入目录 |
| mock 二次守卫（扫 `data/`+`data_unified/` 实文件） | 外部清单会与实际信封脱节 | 每次 `run()` 多两次目录读（41+32 文件，可忽略） |
| 状态 `status_override`，保留 `status_raw` | 6 态全渲染，不丢原始语义 | 前端取值要 `status_override \|\| success` |
| 未知上游格式原样透传留痕 | 不猜数字、不替上游背锅 | 未知格式页面可能显示不全，但有 `bridge.passthrough` 痕迹 |
| 指标注册表"口径与数值分离" | 口径（怎么算）与数值（算多少）必须能各自独立审计 | 新增指标要改两个地方，但改数不改口径会被发现 |
| 排除规则写 `.git/info/exclude` | 不污染上游共用的根 `.gitignore` | 规则不随 clone 分发，换机器要重配 |

### 7.1 密钥链路（D14 新增）

```
密钥（唯一落点：page_prototype/.env，本机私有）
   ├─ 忽略双保险：仓库根 .gitignore 第2行 `.env` ＋ 本机 .git/info/exclude
   │    （后者防上游哪天改了根 .gitignore 时失守；本机私有，不影响其他成员）
   ├─ 注入：bridge/extractor.js loadDotEnv() —— 12 行零依赖，仅在变量缺失时注入
   └─ 守卫：demo/_secret_guard.js 7 项
        ① .env 存在 ② check-ignore 确认被忽略 ③ info/exclude 也排除（双保险）
        ④ git status 看不到它 ⑤ 已跟踪文件（173 个）无密钥
        ⑥ 暂存区无 .env  ⑦ 未跟踪且未忽略文件（41 个）无密钥
```

命中处理顺序（脚本会打印）：**① 立刻在提供方后台吊销**（它已在磁盘上，别等历史清理完）→ ② 值移入 `.env`、代码改读 `process.env` → ③ 确认忽略规则覆盖 → ④ 若已提交过则 `git rm --cached` ＋ 联系领导（历史重写须授权）。

守卫的**误报处理**（复用 D12 教训）：`demo/_engine_check.js` 里有刻意的假密钥（`sk-selftest-NOT-A-REAL-KEY`）用于验证链路活着。
守卫第一版把它当泄漏报了出来 —— **假的警报比没有警报更糟**（没人会一直看红灯）。故放行"同句显式声明为测试/占位"的行，且放行必须显式，不存在"看起来像测试就放过"（那等于给真密钥开后门）。
