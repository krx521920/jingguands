# 确认：D6-AWD-005 的列语义与解析边界

> 回复人：张智博（解析层）　日期：2026-10-02
> 对应阻塞项：「D6-AWD-005 无 header_path，列序回退」

---

## 结论

**「列序回退」这个做法不需要 —— 这个问法本身是错的。**
D6-AWD-005 那张表不是带表头的横表，是**竖排键值表**，字段名就在表格里。

---

## 事实

该表是 **7 行 × 2 列**：

| col=0（字段名） | col=1（值） |
| --- | --- |
| 公司名称 | 江苏众安建设投资（集团）有限公司 |
| 统一社会信用代码 | 91321300575350597U |
| 成立时间 | 2011-05-13 |
| 住所 | 宿迁市宿城区文体中心9楼901室 |
| 法定代表人 | 曹军 |
| 注册资本 | 210,574.5万元人民币 |
| 经营范围 | 建设项目投资；房地产开发、经营；… |

**`header_path` 为空是设计如此，不是漏检。**
解析层对 `n_cols < 3` 的表**一律不判表头行**，理由写在代码里：
窄表多半是「字段名: 值」的键值表，按网格表头处理会把每一行都误当表头。

---

## 消费方规则（明确给抽取与展示两侧）

| 条件 | 表型 | 读法 |
| --- | --- | --- |
| `n_cols < 3` | 竖排键值表 | 按行读：`col=0` 是**字段名**、`col=1` 是**值** |
| `n_cols >= 3` | 网格表 | 按 `header_path` 定位列 |

判别信息在 `tables[]` 的 `n_cols` 字段里，**已存在于现有输出，不需要新增字段或改契约**。

**为什么不需要外部列序映射**：字段名（`公司名称`、`注册资本`…）本身就是 `col=0` 的格子内容。
按行读即可，不存在「哪一列是什么」的不确定性。

**为什么这条规则是安全的**：即便某张两列表其实是「项目 | 金额」这类两列横表，
按键值对读同样成立（左格是名、右格是值）。
