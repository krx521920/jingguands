# D8.2 对齐规则与接口

## 粒度与判定顺序

文档层按“同一签约交易包”关联，输出 `same/different/unknown`，对应魏方B报告 `related/unrelated/unknown`。同交易包可以包含多个转让合同、转让方减持、受让方增持、合计披露；这些动作不自动合并为同一原子事件。原 D8.1 `alignEventPair` 的业务编号＋原子事件规则仍保留，用于已提供业务唯一编号的场景。

| 顺序 | 条件 | 输出/理由 |
|---|---|---|
| 1 | 信封、文件SHA、解析块、主体或可用字段不足；扫描降级；真假混用 | unknown；INSUFFICIENT_SIGNALS，先于负例判断 |
| 2 | 双侧事件类型完全不相交 | different；按质押/权益/中标原子粒度分别保留 |
| 3 | 股权/质押同类型，但标的股票代码明确不同 | different；不同标的证券事件，不推断更高层交易关系 |
| 4 | 中标的每个候选对都同时具有不同采购主体与不同具体项目 | different；公司代码或项目名单独不同均不足以触发 |
| 5 | 同文件SHA、同run_id且事件内容一致 | same source observation；内容冲突则unknown |
| 6 | 同标的公司＋签约日期＋明确受让方＋完整转让方集合，双侧有签约/转让语义块并绑定A事件 | same transaction bundle；只认唯一匹配，多个候选unknown |
| 7 | 同公司、单事件、明确被动稀释且实际发生区间不相交 | different；共享主体或持股数不影响结果 |
| 8 | 区间重叠、只有公司/金额/日期线索、标注不能核验 | unknown，不把“没有判同证据”当成“不同事件” |

金额、币种、税额、联合体份额不参与事件身份判断；不应用汇率、不拆合计、不作传递合并。公告编号只作双侧版本线索，不充当交易编号；文件发布日期不代替发生日/签约日。新增同日同双方多笔独立业务时，应补充业务唯一编号或分别标注交易包；不完整/有歧义的证据不得强制判同。

交易上下文采用显式逐文件标注，校验签约原文、角色与完整转让方集合、A事件的主体/方式/日期/已知方向。它可以识别同交易的不同披露角色，但不代表原子事件全部一致。缺少方向仍可在签约事实足够时建立文档关联，不能据此产生直接字段对。

## 给魏方：两条接口

### 1. `--matcher` 直接兼容入口

```javascript
import { alignEvents } from './src_D8/matching_D8.mjs';
const pairs = alignEvents(envA, envB);
// 同步数组：entityA/entityB/field/valueA/valueB/quoteA/quoteB
// 附加 event_idA/B、evidenceA/B、rule_version，不改既有必需键。
```

仅在文档关联证据成立、同主体同方向且无一对多歧义时返回字段对。当前开放 `shares_before/shares_after/change_shares`：必须有出处、standardized=true、unit=shares、无分母/近似/累计标记，数值可无损承载为安全整数。十进制整数字符串可以无损进入；超出安全整数范围、比例、金额字段留给D9，返回空对而非浮点降级。合计与单人、转让双方、unknown/different均不返回直接对。

在魏方仓库运行（路径改成实际位置；输入目录沿用魏方原名文件）：

```powershell
node scripts/jingguan/verify_crossdoc.mjs --envelopes-dir runs/batch-20261004T093750/envelopes --manifest evaluation/D8/pairs/pairs.dev30.json --matcher "C:/Users/fxc/Desktop/D8/方轩诚_对齐规则与关联解释_D8/src_D8/matching_D8.mjs" --expect --out runs/fang-D8-plugin.json
```

这是**字段对接口兼容**，不是组级判断替换。当前魏源码先算related才调用matcher；matcher即使返回空数组，旧的合计/互补分支仍执行。不能声称此调用在所有未来输入上执行了方方三态规则。实际13/13成绩中，组级关系属于魏引擎；本包另行对方方完整入口评分。

### 2. 完整三态与关联解释入口（推荐）

```javascript
import { alignDocuments, explainGroup } from './src_D8/matching_D8.mjs';
const pair = alignDocuments(envA, envB);
const result = explainGroup({group_id:'业务组ID', members:['case-A','case-B']}, [envA,envB]);
// result.predicted_relation / reasons / a_run_links / member_meta
// result.document_pairs / association_explanation / ui_hint
```

如需把完整规则并入魏B入口，应在任何数值/合计分支前调用 `explainGroup` 或逐对 `alignDocuments`。只有 `same` 的具体文档对才进入后续可比性检查；unknown/different不得执行数值核验。三成员组的不同关系不会通过maxE/maxA或传递闭包拼成同事件。

本交付 `run_public_D8.mjs` 已实现完整公开回放并输出魏B形状报告，宗评分器可以直接消费。`consistency` 三个数组为空且 `consistency_status=not_executed_D8_alignment_only`，明确表示未执行D9，不代表“已经核验且没有矛盾”。

### 新输入的身份上下文

默认上下文只针对本包公开文件SHA。新文档可显式传入：

```javascript
alignDocuments(envA, envB, {
  left: { context: contextA, parsed_document: parseA },
  right: { context: contextB, parsed_document: parseB }
});
```

`context` 结构以 `public_dev_D8/identity_context_D8.json` 为例：file_sha256、可空issuer_code/name/notice_number、transactions[]；交易项包含 kind、event_ids、date、buyer、sellers、statement、binding。fact为 `{value,provenance:[{block_id,page,quote,region}]}`。签约日期为ISO单日，原文必须包含对应日期；角色必须在对应转让条款中出现，转让方集合必须完整。解析文档SHA、块、页码、引文均需一致。禁止将期望标签写入context冒充证据；A 0.3共享Schema不新增这些字段。

## 给陈方：关联解释

保留魏字段：`predicted_relation/reasons/a_run_links`；新增只读解释字段：`member_meta[]` 含 case_id、issuer_code、notice_number、file_sha256、run_id、metadata_evidence；`document_pairs[].evidence/event_pairs` 保留双侧出处。

- `related`显示“同一交易关联”，不能显示“所有字段一致”。
- `unrelated`显示“不同事件”，不展示跨事件金额矛盾。
- `unknown`显示“证据不足／无法判定”，不能归入不同事件。
- 双侧证券代码、公告编号分别显示，null显示“未取得”，不能用另一侧补填。
- region=null仍显示页码＋block_id＋quote；不伪造框坐标。

陈当前分支尚无可验证的D8分组页面入口；本次验证既有A数据桥不受影响，并提供 `关联解释样例_D8.json`，不宣称实际页面已渲染验收。
