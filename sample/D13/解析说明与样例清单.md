## 二、解析流程（六个阶段）

| # | 阶段 | 做什么 | 代码 |
| --- | --- | --- | --- |
| 1 | 取页 | 打开 PDF，逐页取字符/线/图 | `pdfplumber` |
| 2 | 形态判定 | TEXT / SCANNED / MIXED | `parse/doc_form.py` |
| 3 | 表格检测 | 找表、切单元格、补漏检列 | `parse/table_detect.py` |
| 4 | 文本层 | 单元格归属、多层表头、分栏、段落聚类、产出块 | `parse/text_layer.py` |
| 5 | 续表链接 | 跨页续表标注 | `parse/table_link.py` |
| 6 | 组装 | 产出 `evidence/0.9` 文档 | `parse/evidence.py` |

**阶段耗时**（30 份 / 301 页实测）：`form` 85.6% / `text_layer` 9.6% / `tables` 2.8% /
`open` 1.9%；总计中位 **160ms**、每页中位 **43.8ms**。详见 `sample/D12/stage_timing.json`。

**解析是纯本地计算、无模型调用。**

## 三、出处示例（一条证据的完整链路）

每个块带四件套：

```jsonc
{
  "block_id": "d706bf32c_p001_b00007",  // 唯一块号（版本相关）
  "page": 1,
  "region": [90.0, 438.05, 505.32, 496.85],  // PDF 点，原点左上，[l,t,r,b]
  "text_raw": "……（原始字符直拼，不含换行）",
  "source_type": "cell",                  // paragraph / cell / scan_region
  "table_ref": { "table_id": "...", "cell_ref": "r2c3", "header_path": "本次质押数量（股）" }
}
```

**消费方规则**：

- **取字用 `text_raw`**，不要按 `region` 取 → region 是外接矩形，**可以含进相邻块的字符**
- **跨行 quote 先做空白归一** → `text_raw` 不含换行
- **必须带 `block_id`** → 实测 10 组集成案例共 **2009 个块**处于重复文字组，`D5-EQC-002` 一份就有 484 块
- `n_cols < 3` 的表按行读（`col=0` 字段名、`col=1` 值），**不是列序回退**

## 四、扫描边界

| 形态 | 判据 | 产物 |
| --- | --- | --- |
| TEXT | 有可提取字符 | 正常块 |
| SCANNED | 全页无字符 + 图片主导 | `scan_region` 块（带坐标） |
| MIXED | 页内部分区域不可读 | 该区域 `scan_region` 块 |

**扫描件只降级、不识别**：`scan_region` 的 `text_raw` **为空是设计如此**
（它断言「这块读不出字」），`degraded=true`、`missing_reason=NOT_PARSED`。
**它不能作为 `provenance.quote` 的来源。** OCR 入口存在但明确返回不可用。

**无框表格**（纯文本对齐、无边框线）：`tables=0`、内容进正文流、
**列归属语义丢失**。实测 fixture：`tests/fixtures/borderless_table.pdf`。

完整边界表：`src/finstruct/docs/解析能力边界表.md`（＋机器可读 `.json`）。
