## 三、对宗「给张」那条（交接单 §五）的回复

> 原文：`D9-RULE-018` 依赖无框表格的列语义缺失标识；请确认 `D6-AWD-005` 类文档
> 在双侧出处包中显式给出「无 header_path / 列序回退」标记。

**已给出标记，但要更正这条依据的两处偏差：**

### 偏差一：`D6-AWD-005` 不是无框表格

它是 **7 行 × 2 列的竖排键值表**（公司名称 / 统一社会信用代码 / 成立时间 / 住所 /
法定代表人 / 注册资本 / 经营范围）。`header_path` 为空是**设计行为**：
解析层对 `n_cols < 3` 的表一律不判表头行，理由是该类窄表多半是键值表，
按网格表头处理会把每一行都误当表头。

**「无框表格」是另一条边界**（整表未被检出、内容进正文流、列语义真的丢失），
与键值表**原因和补救方式都不同**：

| | 竖排键值表 | 无框表格 |
| --- | --- | --- |
| `header_path` | 必然为空（设计） | 无所谓，整表没检出 |
| 字段名在哪 | **在 `col=0` 的格子里** | 没有列结构 |
| 补救 | **按行读即可，不缺信息** | 只能从连续文本自行判断 |
| 实测 | `D6-AWD-005` | `tests/fixtures/borderless_table.pdf` |

把两者标成同一原因，下游会做多余的动作（对键值表"回退列序"），
而真正需要处理的（无框表格）被漏掉。

### 偏差二：`D9-RULE-018` 引用的块是正文段落，不涉及表格

用例指定的 `ddd80cf89_p001_b00008` 是 `source_type=paragraph`
（region `[90.0, 438.05, 505.32, 496.85]`，quote 为「合同约定总金额为人民币…（含税）」）。
**它落在正文里，不是键值表的单元格** —— 所以「列语义丢失」这件事对该块并不成立。

工具已加**文档级**标记 `doc_narrow_tables`：本次输出对 `D6-AWD-005` 标出
`["ddd80cf89_p001_t001"]`，供下游知道「本文档含键值表」，
同时不误标到那个正文块上。

## 四、「修复缺证据路径」的产出：重锚定建议

工具对块号漂移的条目给出 **`reanchor_suggestions`**，可直接采用：

| 用例 | 字段 | 错误块 | **正确块** |
| --- | --- | --- | --- |
| `D9-RULE-009` | `change_shares` | `…9_b00006` | **`…9_b00015`** |
| `D9-RULE-010` | `pledged_shares_this_time` | `…1_b00024` | **`…1_b00025`** |
| `D9-RULE-012` | `pledged_ratio_this_time_of_held` | `…1_b00025` | **`…1_b00026`** |
| `D9-RULE-012` | `pledged_ratio_this_time_of_total` | `…1_b00026` | **`…1_b00027`** |

**策略：只在 quote 于本文档中唯一命中某块时给修正。**
`D9-RULE-010` 的 `50,350,000` 有**两个候选**（`…b00084` 与 `…b00087`）——
同一数字同时出现在「本次质押后质押股份数量」与「已质押股份限售和冻结数量」两列，
**有歧义就不自动改，交回人工**。这正是不带 `block_id` 会出问题的实例。

## 五、`conflict` 类与「疑似矛盾带双侧证据」

按「判 `conflict` 必须带 ≥2 侧 `block_id + quote`」核了一遍：

- 公开语料中 `conflict` 类**只有 1 条**（`D9-RULE-020`），且是**受控构造**
  （`synthetic_controlled: true`）—— 与宗在 `corpus_boundary` 里声明的
  「公开语料无更正公告、无真矛盾实例（`conflicts=0`）」一致
- 该条两侧的 `block_id` 与 `quote` 字段**齐全**，结构上满足双证据要求

**结论：公开语料里没有真矛盾可核，这一项只能靠受控构造验证结构。**
我不把它说成「已验通过」——受控构造验的是结构，不是真实场景。
