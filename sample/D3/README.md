## 二、D3 修掉的三个真问题

都来自真实公告，不是想出来的。

### 1. `cell_id` 跨表撞车（D2 那个 94/95 的根因）

`cell_id` 原先是**表内序号**，两张表各自从 `c001` 编号。`D3-PLD-001` 第 1 页有两张表，
t002 的 `c001–c035` 直接覆盖了 t001 的同名单元格，导致 **t001 第 1–8 列的字符全部认领失败**、
掉进文本乱序的兜底块。因为它是 dict 静默覆盖，**不抛异常、不给警告**。

修：带 `table_id` 前缀、全文档唯一。单元格块 53 → 88（全部），兜底块 5 → 0。

### 2. 行号推导取错行

原先用 pdfplumber 的 `t.rows[].bbox` 判断「落在第几行」，但它在**纵向合并时会互相重叠**，
取首个命中区间会把第 2 行误判成第 1 行 —— 53 个单元格只推出 20 个唯一 `cell_ref`。

修：从**单元格自身坐标**推网格（相异上边界即行、相异左边界即列），全部表零撞车。

### 3. 居中行无条件合并，把页码吞进正文段落

`cluster_blocks` 里居中分支写的是 `new = False`（无条件与上一行合并），
**完全跳过了间距判据**。于是页面上任何两个居中元素都会并成一块。

实测 `D3-PLD-002` p1 的 `b00037`：正文在 y=632，页面底部页码 `'1'` 在 y=798，
相隔 166pt（行距才 20pt）却被并成一块，`region` 从 632 拉到 808，
白装进整片表格表头，区域重建一致率掉到 **98.9%**。

修：居中行也看间距。多行居中标题的行距正常、仍会连成一块；远离正文的页码正确断开。
修完 5 份全部 100%，且 `D3-PLD-001`/`002`/`003` 各多出 1 块 —— 那是标题与声明句
被正确拆出来的结果。**同一修复也让此前三份文档的标题不再被并进相邻块。**

### 附带：分栏检测的误报护栏

D3 同时补上了欠最久的分栏检测，但第一次跑 5 份新公告时**在 `D3-PLD-003` 第 3 页误报**：
那是落款页，只有 7 行、91 个字符（两条附件说明 + 右对齐署名 + 页码），
右对齐内容在左侧留下空白，而行数少时「干净比例 ≥60%」极易满足 —— 被切成 4 栏。

加了两道护栏：
1. 页面至少 **8 个文本行**才考虑分栏
2. 每一栏必须有**实质内容**（字符数 ≥30 且占比 ≥15%）

修完：5 份公告 + 附加样例共 13 页 `columns` 全为空；合成双栏 fixture 仍正确检出 2 栏。
两条方向相反的用例都进了回归（防误报 / 防护栏过度收紧）。

## 六、给下游的接口

每个表格单元格块带 `table_ref`：

```json
"table_ref": {
  "table_id": "d16c6a948_p001_t002",
  "cell_id": "d16c6a948_p001_t002_c039",
  "cell_ref": "r3c5",
  "row": 2, "col": 4, "rowspan": 1, "colspan": 1,
  "header_path": "本次质押后质押股份数量（股）",
  "continues": null
}
```

映射到两份契约：
- **魏文宇**（抽取契约）：`table_id` → `provenance.table_id`，`cell_ref` → `provenance.cell_ref`，
  `source_type` → `provenance.source_type`
- **宗博文**（评测证据）：`table_id` → `table`，`cell_ref` → `cell`，`source_type` → 分层统计依据

`handoff.field_aliases` 里有完整的三方对照表。

**续表的 `continues` 非空时表示该单元格是被页边界切断的碎片，必须先与指回的那一格拼接再取值。**

## 七、已知边界

1. **续表只打标、不自动拼接**。怎么拼取决于语义（同一单元格的延续 vs 恰好同列的两个
   不同值），解析层不替下游决定。消费方读 `table_ref.continues` 自己拼。
2. **无框表格检不出**。`find_tables()` 依赖绘制线，纯 stream 模式的表格会漏。
3. **分栏检测只处理竖向栏缝**，不处理同栏内的嵌套分栏；表格横跨栏缝时不切栏（给警告）。
4. **表头行判定是启发式**：前导行中「值型单元格 ≤1」即表头行，上限 3 行。
   若某张表的表头里含 ≥2 个纯数字单元格会被误判。
5. **`D3-PLD-005` 有 1 个单元格块 `header_path` 为空** —— 该单元格在表 t001 里，
   而该表的表头判定未触发，属上述启发式的边界情形。
6. **双栏正例是合成 fixture**（`tests/fixtures/twocol_synthetic.pdf`），
   13 份真实文档全是单栏，没有真实正例可用。
7. **`source_type=table` 的兜底取值**当前 5 份里为 0，但代码分支仍在；
   魏文宇的契约枚举 `[paragraph, cell, null]` **需要补上 `table`**，否则将来触发时
   会拒绝整个信封（已作为回复发给他）。
