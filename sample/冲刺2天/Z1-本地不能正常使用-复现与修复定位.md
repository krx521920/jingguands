## 一、结论先行

**页面本身能起、能搬移、数据完整 —— 但第一次用的人按页面提示操作会必然失败。**

失败点是**一句自相矛盾的界面提示**：

> 空状态显示：「**先上传文件**或选择数据集加载」
> 而任何自然上传的文件都被拒：「**仅接受 .json 信封文件**」

**提示叫用户上传文件，上传却一定失败。** 用户据此判定「这页面用不了」——
这与本次冲刺记录里的「用户反馈本地启动后无法正常使用」一致，
也与评审反馈过的「不知怎么用」一致。

## 二、失败步骤（可照做复现）

**环境**：任意机器，Node ≥22（实测 v24.17.0）

```
① cd workspace/cjh/page_prototype
② node server.js
③ 打开 http://127.0.0.1:8642     →  HTTP 200，正常
④ 左栏点「点击或拖入事件信封」，选一份公告 PDF（或 .txt）
⑤ 上传 → 失败
```

**第 ⑤ 步的实测响应（两份都试了）**：

```json
{ "total": 1, "ok": 0, "failed": 1,
  "results": [ { "filename": "test_ann.pdf", "size": 107365,
                 "error": "仅接受 .json 信封文件" } ] }
```

`.txt` 同样报 `仅接受 .json 信封文件`。

## 四、修复定位（两处，都不需要改架构）

### 修复 A（必做，一行文案）：把空状态提示改成真话

**位置**：`workspace/cjh/page_prototype/public/index.html`
**现状**：`先上传文件或选择数据集加载`
**问题**：前半句是假的（上传必失败）

**建议改为**：

> 从左侧下拉选择一个已有数据集 →「加载」。
> **导入仅接受 `.json` 事件信封**；PDF 需先经解析与抽取产出信封。

**理由**：这句话同时告诉用户「现在就能做什么」和「为什么 PDF 不行」。
**成本：一行 HTML，零风险，不动门禁。**

### 修复 B（建议，README 结构）：把启动步骤从「界面重排」小节里挪出来

**位置**：`README.md` 第 6–19 行
**现状**：`## 快速开始` 下面紧接着 `### 本地界面重排（2026-10-08）`，
**启动命令 `node server.js` 被夹在这个 UI 改版说明里**（第 17–19 行）。
**问题**：没有人会在"UI 改版说明"里找"怎么启动"。

**建议**：`## 快速开始` 下先给三行启动，再单列「界面重排」小节。

### 不建议做的

**不要把上传放行 `.pdf/.txt`** —— 这是魏已裁定「维持不做」的。
而且服务端 `N09` 虽然支持 `text` 入参，**页面接了也抽不出**（页面侧没有 PDF 目录、
`cli`/`http` 引擎均未接通）。**放行只会把"立即报错"变成"卡住不动"，更糟。**
