## 零、先看这三条 —— 能省你一轮

1. **上传只收 `.json` 事件信封**。传 PDF / TXT **一定失败**（报「仅接受 .json 信封文件」）。
   **这不是你的环境问题，是设计如此**（页面不做在线抽取）。
2. **正确路径是：左栏下拉选一个数据集 → 点「加载」。** 不要试上传。
3. **只用下拉框里出现的名字**（如 `wei_real_eqc_001`），**不要用 `D5-EQC-001` 这种名字** ——
   后者打不开（`data_unified/` 的 32 份不在下拉框里）。详细见 §五。

## 四、要走通的四步（验收就是这四步）

### ① 输入

左栏下拉选 **`wei_real_pledge_0197`** → 点「加载」。

### ② 结果

中栏出现事件卡片与字段表。**应当看到 14 个字段**（`pledgor` / `pledgee` /
`pledged_shares_this_time` / `pledged_ratio_*` / `start_date` / `end_date` / `purpose` …）。
**界面上的「模拟数据」横幅可以忽略** —— 该数据集是真实信封（这条横幅是待改的文案）。

### ③ 出处

**点中栏字段旁的「证据 ev-xxxx」链接** → 右栏对应证据卡高亮并滚动到位。
证据里应能看到 `block_id` / `page` / `bbox` / `source_type` / `cell_ref` / `header_path`。

**这一步是整条链的关键**：它证明「字段能回指到原文块」，不是只给一个值。

### ④ 导出

点「导出 CSV」与「导出 JSON」，各存一份。

### 别名对照（`D*-*` 名 → 下拉框里能选的名）

`data_unified/` 的 32 份里，**21 份**可由 `data/` 的 `wei_real_*` 别名打开，
**11 份打不开**（完整表见 `Z3-录制输入与20页PDF.json`）。常用的几对：

| 权威名 | 下拉框里选这个 |
| --- | --- |
| `D4-PLD-001` | `wei_real_pledge_0197` |
| `D5-EQC-001` | `wei_real_eqc_001` |
| `D5-EQC-002` | `wei_real_eqc_002` |

（判据：两者 `source.file_id` 相同；例 `D5-EQC-001` 与 `wei_real_eqc_001`
的 `file_id` 都是 `sha256:9d5be14f…`。）
