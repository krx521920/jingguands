### 对 D12 性能目标（3 份 20 页公告各 ≤90 秒）的意义

**解析是纯本地计算、无模型调用。** 实测 16 页以上文档的解析耗时：

| 文档 | 页 | 解析耗时 |
| --- | ---: | ---: |
| `D5-EQC-002` | 64 | **2554ms** |
| `D5-EQC-003` | 34 | 1964ms |
| `D5-EQC-001` | 35 | 1327ms |
| `D5-EQC-004` | 21 | 634ms |

即 **20 页级文档的解析在 1 秒上下**，相对 90 秒预算占比 **~1%**。
**结论：≤90 秒的瓶颈不在解析侧** —— 若端到端超时，应看模型调用与并发，不是解析。

## 二、解析修复：形态判定的像素循环

### 定位

耗时表显示 **`form` 一项吃掉 85.6%**，远超它该有的比重。
进入该阶段后定位到 `doc_form.ink_ratio`：

```python
# 修复前
px = small.load()
dark = 0
for y in range(h):
    for x in range(w):
        if px[x, y] < threshold:
            dark += 1
```

**在 400×566 上要跑 22 万次 Python 循环**，每个需要判定的页面都付一次这个代价。

### 修复

改用 `Image.histogram()`（C 层一次返回 256 个灰度桶）：

```python
hist = small.histogram()
dark = sum(hist[:threshold])
```

**这是等价改写，不是近似** —— `< threshold` 的像素数就是 `hist[:threshold]` 之和。

### 等价性验证（这是本次修复的关键证据）

对 **37 份**交付文档逐份重新解析，比对 `text_raw` **与 `form` 判定**：

| 结果 | 份数 |
| --- | ---: |
| **逐字相同** | **37** |
| 有变化 | **0** |

形态判定结果也未变 —— 说明不是"改得差不多"，而是**逐位等价**。
88 条回归全绿。

### 效果（三次重复测量，避免把机器波动当收益）

| | 优化前 | 优化后（3 次） | 波动 |
| --- | ---: | --- | ---: |
| 总耗时 | 17061ms | 12502 / 12176 / 12706ms | **4.4%** |
| `form` 阶段 | 14557ms | 10698 / 10418 / 10850ms | — |
| 每页中位 | 56.5ms | 43.8ms | — |

**优化后最小值比优化前低 28.6%，而三次测量波动只有 4.4%** ——
收益远超噪声，是真实优化，不是我挑了一次好看的数。

### 剩余的 `form` 占比

优化后 `form` **仍占 85.6%**。剩余成本在 `page.render()`（PDFium 渲染页面本身）。
**那是渲染调用，不是可去掉的算法开销** —— 只要走「渲染判墨迹」这条路就绕不开。
若将来要进一步优化，只能改判据（例如用 PDF 的图片对象面积判断是否扫描页，
完全跳过渲染），但那会改变判定语义，需单独立项评估。

## 四、诚实边界
