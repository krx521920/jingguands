## 一、交付：重锚定工具

`tools/reanchor_provenance.py` —— 输入「待修正的溯源条目」＋「当前版本 parse」，
输出每条的新 `block_id`，或说明**为什么不能自动改**。

```bash
python tools/reanchor_provenance.py --miss <l3_miss.json> --parse <当前.parse.json> -o <输出.json>
```

**判定分三档，只自动改第一档**：

| 状态 | 处置 |
| --- | --- |
| `remapped` | 自动给出新 `block_id`（quote 在当前 parse 唯一/首个命中） |
| `spans_blocks` | 给出候选，**人工确认**（quote 跨多个块，需拼接） |
| `not_found` | **不自动改** —— 硬塞会伪造出处 |

**为什么第三档不自动改**：`not_found` 有两种成因，处置完全不同 ——
**块号错位**（可重映射）vs **quote 本身是旧版拍平的产物**（必须先重新取 quote）。
机器分不清这两者，硬选一个就是编造出处。

## 二、我发现的一个实质性障碍（需要群里定）

**这 10 条里有一部分 quote 本身就是「跨单元格拍平」的产物，不只是块号错位。**

看这几条（原文照抄）：

| 字段 | quote |
| --- | --- |
| `pledged_shares_this_time` | `合计——7,800,0008.92%3.66%` |
| `pledged_ratio_this_time_of_held` | `合计——7,800,0008.92%3.66%` |
| `start_date` | `2026年09月是2,100,0002.40%0.99%否否23日` |

这些**不是自然语句**：`7,800,000` 紧接 `8.92%` 紧接 `3.66%`，
`2026年09月` 里插进了 `是`、`2,100,000`、`2.40%`、`0.99%`、`否否`。
这是**旧版把多个单元格的文本拍平进一个块**的结果 —— 与陈查到的根因一致
（0.3.0 的 `tables[].cells` 为空数组，单元格文本是独立 block）。

**后果**：对这些条目，**只重映射 `block_id` 是不够的** ——
新版本已经把单元格分开了，那段拍平文本在任何单个块里都不存在。
**必须连同 `quote` 一起从当前 parse 重新取。**

**这一点请群里定口径**：是「重映射 + 重取 quote」还是「该批次作废、按当前版本重跑」。
我不自行决定 —— 前者会改动证据文本，后者会改动分数分母。
