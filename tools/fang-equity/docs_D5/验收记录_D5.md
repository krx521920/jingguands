## 实际兼容差异

1. 宗博文 10 份 Gold 都已有两处公共 Schema 差异：`source.parse_meta.blocks` 为整数而 Schema 要求 array/null，`run_meta.note` 未被 Schema 注册。核验报告保留这些原始输入；兼容结果列出错误，未改标注或冒称格式 100% 通过。六份上游输出均通过该公共校验。
2. 上游 D5-EQC-001 的部分 `change_shares` 为负数，而评测定义为非负绝对量。本工具输出 SIGNED_CHANGE_REQUIRES_MAPPING，不自动改成绝对值；需要上游明确适配后再验收。原始负号在 raw_value、标准化绝对量在 value 的 Gold 表达可以直接消费。
3. Gold 的 001、007、008、009 通过适用关系核验；002、003 缺前后值；004、005、010 存在日期待复核；006 股数不变而比例下降，需要分母复核。这些待复核结果是输入现状，不是程序测试失败。
4. 共同 Schema 允许 `standardized` 可选；本工具不把缺少该标记的数值认作已标准化，而是保留候选并提示复核。文本字段无需该标记即可使用。单日 `change_date` 和有序 ISO 日期区间均接受，日期真实有效性单独检查。
5. 解析块回查存在两处原文子串不匹配：D5-EQC-007/E01/direction、D5-EQC-010/E01/change_date。block_id 和页码可定位，但 Gold quote 不是对应 text_raw 的严格子串；详细引用在 compatibility_results 的 parser_references 中。本次未修改 Gold，也未将这些字段认证为原文已核真；007 的数值关系通过不代表其方向出处已经通过。
